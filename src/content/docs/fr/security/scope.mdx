Une portée est une manière granulaire de définir le comportement autorisé ou interdit d'une commande Tauri.

Les portées sont classées en portées `allow` ou `deny`, où `deny` l'emporte toujours sur `allow`.

Le type de portée doit être n'importe quel type sérialisable par [`serde`](https://docs.rs/serde/latest/serde/). En général, ces types sont propres au plugin. Pour les commandes avec portée implémentées dans une application Tauri, le type de portée doit être défini dans l'application, puis appliqué dans l'implémentation de la commande.

Par exemple, le plugin [`Fs`](https://github.com/tauri-apps/plugins-workspace/tree/v2/plugins/fs) vous permet d'utiliser des portées pour autoriser ou refuser certains répertoires et fichiers, et le plugin [`http`](https://github.com/tauri-apps/plugins-workspace/tree/v2/plugins/http) utilise des portées pour filtrer les URL autorisées.

La portée est transmise à la commande, et son traitement ou son application correcte est implémenté par la commande elle-même.

:::caution

Les développeurs de commandes doivent s'assurer qu'aucun contournement de portée n'est possible. L'implémentation de validation des portées doit être auditée pour garantir sa correction.

:::

## Exemples

Ces exemples sont tirés des permissions du plugin [`Fs`](https://github.com/tauri-apps/plugins-workspace/tree/v2/plugins/fs) :

Le type de portée de ce plugin, pour toutes les commandes, est une chaîne de caractères contenant un chemin compatible avec [`glob`](https://docs.rs/glob/latest/glob/).

```toml title="plugins/fs/permissions/autogenerated/base-directories/applocaldata.toml"
[[permission]]
identifier = "scope-applocaldata-recursive"
description = '''
This scope recursive access to the complete `$APPLOCALDATA` folder,
including sub directories and files.
'''

[[permission.scope.allow]]
path = "$APPLOCALDATA/**"
```

```toml title="plugins/fs/permissions/deny-webview-data.toml"
[[permission]]
identifier = "deny-webview-data-linux"
description = '''
This denies read access to the
`$APPLOCALDATA` folder on linux as the webview data and
configuration values are stored here.
Allowing access can lead to sensitive information disclosure and
should be well considered.
'''
platforms = ["linux"]

[[permission.scope.deny]]
path = "$APPLOCALDATA/**"

[[permission]]
identifier = "deny-webview-data-windows"
description = '''
This denies read access to the
`$APPLOCALDATA/EBWebView` folder on windows as the webview data and
configuration values are stored here.
Allowing access can lead to sensitive information disclosure and
should be well considered.
'''
platforms = ["windows"]

[[permission.scope.deny]]
path = "$APPLOCALDATA/EBWebView/**"
```

Les portées ci-dessus peuvent être utilisées pour autoriser l'accès au dossier `APPLOCALDATA`, tout en empêchant l'accès au sous-dossier `EBWebView` sous Windows, qui contient des données sensibles de webview.

Elles peuvent être fusionnées dans un ensemble, ce qui réduit la configuration dupliquée et la rend plus compréhensible pour toute personne qui examine la configuration de l'application.

D'abord, les portées de refus sont fusionnées dans `deny-default` :

```toml title="plugins/fs/permissions/deny-default.toml"
[[set]]
identifier = "deny-default"
description = '''
This denies access to dangerous Tauri relevant files and
folders by default.
'''
permissions = ["deny-webview-data-linux", "deny-webview-data-windows"]
```

Ensuite, les portées de refus et d'autorisation sont fusionnées :

```toml
[[set]]
identifier = "scope-applocaldata-reasonable"
description = '''
This scope set allows access to the `APPLOCALDATA` folder and
subfolders except for linux,
while it denies access to dangerous Tauri relevant files and
folders by default on windows.
'''
permissions = ["scope-applocaldata-recursive", "deny-default"]
```

Ces portées peuvent être utilisées soit pour toutes les commandes, en étendant la portée globale du plugin, soit uniquement pour certaines commandes lorsqu'elles sont utilisées avec une commande activée dans une permission.

Un accès raisonnable en lecture seule aux fichiers dans `APPLOCALDATA` pourrait ressembler à ceci :

```toml
[[set]]
identifier = "read-files-applocaldata"
description = '''
This set allows file read access to the `APPLOCALDATA` folder and
subfolders except for linux,
while it denies access to dangerous Tauri relevant files and
folders by default on windows.'''
permissions = ["scope-applocaldata-reasonable", "allow-read-file"]
```

Ces exemples ne mettent en évidence que la fonctionnalité de portée elle-même. Chaque développeur de plugin ou d'application doit réfléchir à des combinaisons de portées raisonnables selon ses cas d'utilisation.
