Les permissions décrivent les privilèges explicites des commandes.

```toml
[[permission]]
identifier = "my-identifier"
description = "This describes the impact and more."
commands.allow = [
    "read_file"
]

[[permission.scope.allow]]
my-scope = "$HOME/*"

[[permission.scope.deny]]
my-scope = "$HOME/secret"
```

Elles peuvent rendre des commandes accessibles dans le frontend d'une application Tauri. Elles peuvent associer des portées à des commandes et définir quelles commandes sont activées. Les permissions peuvent autoriser ou refuser certaines commandes, définir des portées ou combiner les deux.

Pour accorder ou refuser une permission à une fenêtre ou webview de votre app, vous devez référencer la permission dans une [capacité](/fr/security/capabilities/).

Les permissions peuvent être regroupées dans un ensemble sous un nouvel identifiant. C'est ce qu'on appelle un ensemble de permissions. Cela vous permet de combiner des permissions liées aux portées avec des permissions liées aux commandes. Cela permet aussi de regrouper ou d'assembler des permissions propres à un système d'exploitation dans des ensembles plus faciles à utiliser.

En tant que développeur de plugin, vous pouvez fournir plusieurs permissions prédéfinies et bien nommées pour toutes les commandes que vous exposez.

En tant que développeur d'application, vous pouvez étendre les permissions de plugins existantes ou en définir pour vos propres commandes. Elles peuvent être regroupées ou étendues dans un ensemble afin d'être réutilisées ou de simplifier plus tard les fichiers de configuration principaux.

## Identifiant de permission

L'identifiant des permissions sert à garantir qu'elles peuvent être réutilisées et qu'elles ont des noms uniques.

:::tip

Par **name**, nous désignons le nom du crate du plugin sans le préfixe `tauri-plugin-`. Il sert d'espace de noms pour réduire les risques de conflits de noms. Lorsque vous référencez les permissions de l'application elle-même, il n'est pas nécessaire.

:::

- `<name>:default` indique que la permission est la permission par défaut d'un plugin ou d'une application
- `<name>:<command-name>` indique que la permission concerne une commande individuelle

Le préfixe de plugin `tauri-plugin-` est automatiquement ajouté à l'identifiant des plugins au moment de la compilation et n'a pas besoin d'être spécifié manuellement.

Les identifiants sont limités aux caractères alphabétiques ASCII minuscules `[a-z]` et la longueur maximale de l'identifiant est actuellement limitée à `116` en raison des constantes suivantes :

```rust
const IDENTIFIER_SEPARATOR: u8 = b':';
const PLUGIN_PREFIX: &str = "tauri-plugin-";

// https://doc.rust-lang.org/cargo/reference/manifest.html#the-name-field
const MAX_LEN_PREFIX: usize = 64 - PLUGIN_PREFIX.len();
const MAX_LEN_BASE: usize = 64;
const MAX_LEN_IDENTIFIER: usize = MAX_LEN_PREFIX + 1 + MAX_LEN_BASE;
```

## Fichiers de configuration

Exemple simplifié de structure de répertoire pour un **plugin** Tauri :

```sh
tauri-plugin
├── README.md
├── src
│  └── lib.rs
├── build.rs
├── Cargo.toml
├── permissions
│  └── <identifier>.json/toml
│  └── default.json/toml
```

La permission par défaut est traitée de manière particulière : elle est automatiquement ajoutée à la configuration de l'application, tant que la CLI Tauri est utilisée pour ajouter des plugins à une application Tauri.

Pour les développeurs d'**application**, la structure est similaire :

```sh
tauri-app
├── index.html
├── package.json
├── src
├── src-tauri
│   ├── Cargo.toml
│   ├── permissions
│      └── <identifier>.toml
|   ├── capabilities
│      └── <identifier>.json/.toml
│   ├── src
│   ├── tauri.conf.json
```

:::note

En tant que développeur d'application, les fichiers de capacités peuvent être écrits en `json`/`json5` ou `toml`, tandis que les permissions ne peuvent être définies qu'en `toml`.

:::

## Exemples

Exemples de permissions du plugin `File System`.

```toml title="plugins/fs/permissions/autogenerated/base-directories/home.toml"
[[permission]]
identifier = "scope-home"
description = """This scope permits access to all files and
list content of top level directories in the `$HOME`folder."""

[[permission.scope.allow]]
path = "$HOME/*"
```

```toml title="plugins/fs/permissions/read-files.toml"
[[permission]]
identifier = "read-files"
description = """This enables all file read related
commands without any pre-configured accessible paths."""
commands.allow = [
    "read_file",
    "read",
    "open",
    "read_text_file",
    "read_text_file_lines",
    "read_text_file_lines_next"
]
```

```toml title="plugins/fs/permissions/autogenerated/commands/mkdir.toml"
[[permission]]
identifier = "allow-mkdir"
description = "This enables the mkdir command."
commands.allow = [
    "mkdir"
]
```

Exemple d'implémentation étendant les permissions de plugin ci-dessus dans votre app :

```toml title="my-app/src-tauri/permissions/home-read-extends.toml"
[[set]]
identifier = "allow-home-read-extended"
description = """ This allows non-recursive read access to files and to create directories
in the `$HOME` folder.
"""
permissions = [
    "fs:read-files",
    "fs:scope-home",
    "fs:allow-mkdir"
]
```
