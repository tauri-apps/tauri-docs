L'objectif de cet exercice est de mieux comprendre comment créer des permissions de plugins lorsque vous écrivez votre propre plugin.

À la fin, vous saurez créer des permissions simples pour vos plugins. Vous disposerez d'un exemple de plugin Tauri où les permissions sont partiellement générées automatiquement et partiellement écrites à la main.

<Steps>

1. ### Créer un plugin Tauri

    Dans notre exemple, nous utiliserons la [`cli`](/fr/reference/cli/) Tauri pour générer la structure de code source d'un plugin Tauri. Assurez-vous d'avoir installé tous les [prérequis](/fr/start/prerequisites/) et vérifiez que vous avez la bonne version de la CLI Tauri en exécutant `cargo tauri info`.

    La sortie devrait indiquer que la version de `tauri-cli` est `2.x`. Dans cette explication étape par étape, nous utiliserons `pnpm`, mais vous pouvez choisir un autre gestionnaire de paquets et le remplacer dans les commandes en conséquence.

    Une fois une version récente installée, vous pouvez créer le plugin avec la CLI Tauri.

    <ShowSolution>
    ```sh
    mkdir -p tauri-learning
    cd tauri-learning
    cargo tauri plugin new test
    cd tauri-plugin-test
    pnpm install
    pnpm build
    cargo build
    ```
    </ShowSolution>

2. ### Créer une nouvelle commande

    Pour montrer quelque chose de pratique et simple, supposons que notre commande écrive une saisie utilisateur dans un fichier de notre dossier temporaire, tout en ajoutant un en-tête personnalisé au fichier.

    Appelons notre commande `write_custom_file`, implémentons-la dans `src/commands.rs` et ajoutons-la au builder de notre plugin afin de l'exposer au frontend.

    Les utilitaires du coeur de Tauri généreront automatiquement les permissions `allow` et `deny` pour cette commande, nous n'avons donc pas à nous en occuper.

    <ShowSolution>

    L'implémentation de la commande :

    ```rust title="src/commands.rs" ins={15-22} ins=", Manager"
    use tauri::{AppHandle, command, Runtime};

    use crate::models::*;
    use crate::Result;
    use crate::TestExt;

    #[command]
    pub(crate) async fn ping<R: Runtime>(
        app: AppHandle<R>,
        payload: PingRequest,
    ) -> Result<PingResponse> {
        app.test1().ping(payload)
    }

    #[command]
    pub(crate) async fn write_custom_file<R: Runtime>(
        user_input: String,
        app: AppHandle<R>,
    ) -> Result<String> {
        std::fs::write(app.path().temp_dir().unwrap(), user_input)?;
        Ok("success".to_string())
    }

    ```

    Générer automatiquement les permissions intégrées pour votre nouvelle commande :

    ```rust title="src/build.rs" ins="\"write_custom_file\""
    const COMMANDS: &[&str] = &["ping", "write_custom_file"];
    ```

    Ces permissions intégrées seront générées automatiquement par le système de build Tauri et seront visibles dans le dossier `permissions/autogenerated/commands`. Par défaut, une permission `enable-<command>` et une permission `deny-<command>` seront créées.

    </ShowSolution>
3. ### Exposer la nouvelle commande

    L'étape précédente consistait à écrire l'implémentation réelle de la commande. Nous voulons maintenant l'exposer au frontend pour qu'elle puisse être utilisée.

    <ShowSolution>

    Configurez le builder Tauri pour générer le invoke handler qui transmettra les requêtes IPC frontend à la commande nouvellement implémentée :

    ```rust title="src/lib.rs"  ins="commands::write_custom_file,"
    pub fn init<R: Runtime>() -> TauriPlugin<R> {
    Builder::new("test")
        .invoke_handler(tauri::generate_handler![
            commands::ping,
            commands::write_custom_file,
        ])
        .setup(|app, api| {
            #[cfg(mobile)]
            let test = mobile::init(app, api)?;
            #[cfg(desktop)]
            let test = desktop::init(app, api)?;
            app.manage(test);

            // manage state so it is accessible by the commands
            app.manage(MyState::default());
            Ok(())
        })
        .build()
    }
    ```

    Exposez la nouvelle commande dans le module frontend.

    Cette étape est essentielle pour que l'application d'exemple puisse importer correctement le module frontend. C'est pratique et n'a pas d'impact sur la sécurité, puisque le command handler est déjà généré et que la commande peut être appelée manuellement depuis le frontend.

    ```ts title="guest-js/index.ts" ins={11-13}
    import { invoke } from '@tauri-apps/api/core'

    export async function ping(value: string): Promise<string | null> {
      return await invoke<{value?: string}>('plugin:test|ping', {
        payload: {
          value,
        },
      }).then((r) => (r.value ? r.value : null));
    }

    export async function writeCustomFile(user_input: string): Promise<string> {
     return await invoke('plugin:test|write_custom_file',{userInput: user_input});
    }
    ```

    :::tip
    Le paramètre d'invocation doit être en CamelCase. Dans cet exemple, il s'agit de `userInput` au lieu de `user_input`.
    :::

    Assurez-vous que votre paquet est construit :

    ```
    pnpm build
    ```

    </ShowSolution>

4. ### Définir les permissions par défaut du plugin

    Comme notre plugin devrait exposer la commande `write_custom_file` par défaut, nous devons l'ajouter à notre permission `default.toml`.

    <ShowSolution>
    Ajoutez ceci à notre ensemble de permissions par défaut pour autoriser la nouvelle commande que nous venons d'exposer.

    ```toml title="permissions/default.toml" ins=", \"allow-write-custom-file\""
    "$schema" = "schemas/schema.json"
    [default]
    description = "Default permissions for the plugin"
    permissions = ["allow-ping", "allow-write-custom-file"]
    ```
    </ShowSolution>

5. ### Appeler la commande de test depuis l'application d'exemple

    La structure du répertoire de plugin créée contient un dossier `examples/tauri-app`, qui fournit une application Tauri prête à l'emploi pour tester le plugin.

    Comme nous avons ajouté une nouvelle commande, nous devons légèrement modifier le frontend pour appeler cette nouvelle commande.

    <ShowSolution>
    ```svelte title="src/App.svelte" del={11-13,42-45} ins={14-16,45-49}
    <script>
      import Greet from './lib/Greet.svelte'
      import { ping, writeCustomFile } from 'tauri-plugin-test-api'

      let response = ''

      function updateResponse(returnValue) {
        response += `[${new Date().toLocaleTimeString()}]` + (typeof returnValue === 'string' ? returnValue : JSON.stringify(returnValue)) + '<br>'
      }

      function _ping() {
        ping("Pong!").then(updateResponse).catch(updateResponse)
      }
      function _writeCustomFile() {
        writeCustomFile("HELLO FROM TAURI PLUGIN").then(updateResponse).catch(updateResponse)
      }
    </script>

    <main class="container">
      <h1>Welcome to Tauri!</h1>

      <div class="row">
        <a href="https://vitejs.dev" target="_blank">
          <img src="/vite.svg" class="logo vite" alt="Vite Logo" />
        </a>
        <a href="https://tauri.app" target="_blank">
          <img src="/tauri.svg" class="logo tauri" alt="Tauri Logo" />
        </a>
        <a href="https://svelte.dev" target="_blank">
          <img src="/svelte.svg" class="logo svelte" alt="Svelte Logo" />
        </a>
      </div>

      <p>
        Click on the Tauri, Vite, and Svelte logos to learn more.
      </p>

      <div class="row">
        <Greet />
      </div>

      <div>
        <button on:click="{_ping}">Ping</button>
        <div>{@html response}</div>
      </div>
      <div>
        <button on:click="{_writeCustomFile}">Write</button>
        <div>{@html response}</div>
      </div>


    </main>

    <style>
      .logo.vite:hover {
        filter: drop-shadow(0 0 2em #747bff);
      }

      .logo.svelte:hover {
        filter: drop-shadow(0 0 2em #ff3e00);
      }
    </style>
    ```

    En exécutant cela et en appuyant sur le bouton « Write », vous devriez obtenir :

    ```
    success
    ```

    Et vous devriez trouver un fichier `test.txt` dans votre dossier temporaire contenant un message provenant de notre nouvelle commande de plugin implémentée.
    🥳

    </ShowSolution>
