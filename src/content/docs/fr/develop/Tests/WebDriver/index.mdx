[WebDriver] est une interface standardisée pour interagir avec des documents web, principalement destinée aux tests automatisés. La
méthode recommandée pour l'utiliser avec Tauri est [WebdriverIO] et [`@wdio/tauri-service`], qui fonctionnent sous **Windows, Linux
et macOS**. Maintenu dans le projet WebdriverIO, ce service fournit un accès aux API Tauri via `browser.tauri.execute()`,
le mock de commandes (IPC), la capture des logs frontend et backend, et multiremote.

Par défaut, le service exécute un **serveur WebDriver embarqué** dans votre app, donc aucun driver externe n'est nécessaire sur aucune
plateforme, et c'est ainsi que macOS est pris en charge. Il peut aussi piloter le WebDriver natif de la plateforme via [`tauri-driver`]
sous Windows et Linux, ou le fork multiplateforme de `tauri-driver` de [CrabNebula] sur toutes les plateformes (une clé d'API payante est
requise pour macOS). Quelle que soit l'option choisie, le service détecte le binaire de votre application et, avec la voie `tauri-driver`,
maintient pour vous le WebDriver Edge synchronisé sous Windows.

La façon la plus rapide de scaffolder un projet est le starter WebdriverIO :

```shell
npm create wdio@latest ./
```

Choisissez **Desktop Testing**, puis **Tauri** à l'invite du framework. Une configuration minimale ressemble à ceci :

```typescript
export const config: WebdriverIO.Config = {
  services: [
    [
      'tauri',
      {
        appBinaryPath: './src-tauri/target/release/my-tauri-app',
        driverProvider: 'embedded',
      },
    ],
  ],
};
```

Cette configuration utilise deux petits plugins Tauri, tous deux optionnels selon vos besoins :

- **`tauri-plugin-wdio-webdriver`** exécute le serveur WebDriver embarqué. Il est requis pour le provider `embedded` (par
  défaut) : le service pilote votre app à travers lui, sans driver externe, et c'est ainsi que macOS est pris en charge. Vous pouvez
  l'ignorer si vous voulez utiliser le provider `external` ou `crabnebula` à la place.
- **`tauri-plugin-wdio`** active l'accès backend, notamment `browser.tauri.execute()`, le mock de commandes (IPC) et la capture
  des logs.

Consultez [Configuration du plugin] pour les étapes complètes, ainsi que le [guide de configuration CrabNebula] si vous utilisez ce provider.

Pour les tests rapides limités au renderer, il existe aussi un **mode navigateur** qui exécute votre frontend Tauri dans Chrome standard avec un
serveur de développement Vite : aucun binaire Tauri, driver ou plugin n'est requis. Il intercepte les appels `invoke()` afin que vous puissiez mocker les commandes
et faire des assertions sur leurs arguments avec la même API WDIO. Consultez le [guide du mode navigateur].

## Piloter `tauri-driver` directement

Si vous n'utilisez pas Node.js, préférez [Selenium], ou intégrez WebDriver dans un harnais de test personnalisé, vous pouvez piloter
[`tauri-driver`] directement au lieu d'utiliser le service. Piloté directement, seuls Windows et Linux sont pris en charge sur
desktop, car macOS ne dispose d'aucun outil driver WKWebView (utilisez le serveur WebDriver embarqué du service pour macOS).
