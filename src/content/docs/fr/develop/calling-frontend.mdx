Ce document explique comment communiquer avec le frontend de votre application depuis votre code Rust.
Pour voir comment communiquer avec votre code Rust depuis votre frontend, consultez [Appeler Rust depuis le frontend].

Le côté Rust de votre application Tauri peut appeler le frontend en utilisant le système d'événements Tauri,
des channels, ou en évaluant directement du code JavaScript.

## Système d'événements

Tauri fournit un système d'événements simple que vous pouvez utiliser pour établir une communication bidirectionnelle entre Rust et votre frontend.

Le système d'événements a été conçu pour les situations où de petites quantités de données doivent être diffusées
ou lorsque vous devez implémenter un modèle multi-consommateurs multi-producteurs (par exemple un système de notifications push).

Le système d'événements n'est pas conçu pour les situations nécessitant une faible latence ou un haut débit.
Consultez la [section sur les channels](#channels) pour l'implémentation optimisée pour le streaming de données.

Les principales différences entre une commande Tauri et un événement Tauri sont que les événements n'ont pas de prise en charge forte des types,
que leurs payloads sont toujours des chaînes JSON, ce qui les rend peu adaptés aux gros messages,
et qu'ils ne prennent pas en charge le système de [capabilities] pour contrôler finement les données et les canaux d'événements.

Les types [AppHandle] et [WebviewWindow] implémentent les traits du système d'événements [Listener] et [Emitter].

Les événements sont soit globaux (livrés à tous les écouteurs), soit propres à une webview (livrés uniquement à la webview correspondant à un label donné).

### Événements globaux

Pour déclencher un événement global, vous pouvez utiliser la fonction [Emitter#emit] :

```rust title="src-tauri/src/lib.rs"
use tauri::{AppHandle, Emitter};

#[tauri::command]
fn download(app: AppHandle, url: String) {
  app.emit("download-started", &url).unwrap();
  for progress in [1, 15, 50, 80, 100] {
    app.emit("download-progress", progress).unwrap();
  }
  app.emit("download-finished", &url).unwrap();
}
```

:::note
Les événements globaux sont livrés à **tous** les écouteurs.
:::

### Événement de webview

Pour déclencher un événement vers un écouteur enregistré par une webview spécifique, vous pouvez utiliser la fonction [Emitter#emit_to] :

```rust title="src-tauri/src/lib.rs"
use tauri::{AppHandle, Emitter};

#[tauri::command]
fn login(app: AppHandle, user: String, password: String) {
  let authenticated = user == "tauri-apps" && password == "tauri";
  let result = if authenticated { "loggedIn" } else { "invalidCredentials" };
  app.emit_to("login", "login-result", result).unwrap();
}
```

Il est aussi possible de déclencher un événement vers une liste de webviews en appelant [Emitter#emit_filter].
Dans l'exemple suivant, nous émettons un événement open-file vers les webviews main et file-viewer :

```rust title="src-tauri/src/lib.rs"
use tauri::{AppHandle, Emitter, EventTarget};

#[tauri::command]
fn open_file(app: AppHandle, path: std::path::PathBuf) {
  app.emit_filter("open-file", path, |target| match target {
    EventTarget::WebviewWindow { label } => label == "main" || label == "file-viewer",
    _ => false,
  }).unwrap();
}
```

:::note
Les événements propres à une webview ne sont **pas** déclenchés vers les écouteurs globaux classiques.
Pour écouter **n'importe quel** événement, vous devez utiliser la fonction `listen_any` au lieu de `listen`,
qui définit l'écouteur comme un collecteur global pour les événements émis.
:::

### Payload d'événement

Le payload d'événement peut être n'importe quel type [sérialisable][Serialize] qui implémente aussi [Clone].
Améliorons l'exemple d'événement de téléchargement en utilisant un objet pour émettre plus d'informations dans chaque événement :

```rust title="src-tauri/src/lib.rs"
use tauri::{AppHandle, Emitter};
use serde::Serialize;

#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase")]
struct DownloadStarted<'a> {
  url: &'a str,
  download_id: usize,
  content_length: usize,
}

#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase")]
struct DownloadProgress {
  download_id: usize,
  chunk_length: usize,
}

#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase")]
struct DownloadFinished {
  download_id: usize,
}

#[tauri::command]
fn download(app: AppHandle, url: String) {
  let content_length = 1000;
  let download_id = 1;

  app.emit("download-started", DownloadStarted {
    url: &url,
    download_id,
    content_length
  }).unwrap();

  for chunk_length in [15, 150, 35, 500, 300] {
    app.emit("download-progress", DownloadProgress {
      download_id,
      chunk_length,
    }).unwrap();
  }

  app.emit("download-finished", DownloadFinished { download_id }).unwrap();
}
```

## Channels

Le système d'événements est conçu comme une communication bidirectionnelle simple, disponible globalement dans votre application.
Sous le capot, il évalue directement du code JavaScript ; il peut donc ne pas être adapté à l'envoi d'une grande quantité de données.

Les channels sont conçus pour être rapides et livrer des données ordonnées. Ils sont utilisés en interne pour les opérations de streaming
comme la progression de téléchargement, la sortie des processus enfants et les messages WebSocket.

Réécrivons notre exemple de commande de téléchargement pour utiliser des channels au lieu du système d'événements :

```rust title="src-tauri/src/lib.rs"
use tauri::{AppHandle, ipc::Channel};
use serde::Serialize;

#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase", rename_all_fields = "camelCase", tag = "event", content = "data")]
enum DownloadEvent<'a> {
  Started {
    url: &'a str,
    download_id: usize,
    content_length: usize,
  },
  Progress {
    download_id: usize,
    chunk_length: usize,
  },
  Finished {
    download_id: usize,
  },
}

#[tauri::command]
fn download(app: AppHandle, url: String, on_event: Channel<DownloadEvent>) {
  let content_length = 1000;
  let download_id = 1;

  on_event.send(DownloadEvent::Started {
    url: &url,
    download_id,
    content_length,
  }).unwrap();

  for chunk_length in [15, 150, 35, 500, 300] {
    on_event.send(DownloadEvent::Progress {
      download_id,
      chunk_length,
    }).unwrap();
  }

  on_event.send(DownloadEvent::Finished { download_id }).unwrap();
}
```

Lorsque vous appelez la commande `download`, vous devez créer le channel et le fournir comme argument :

```ts
import { invoke, Channel } from '@tauri-apps/api/core';

type DownloadEvent =
  | {
      event: 'started';
      data: {
        url: string;
        downloadId: number;
        contentLength: number;
      };
    }
  | {
      event: 'progress';
      data: {
        downloadId: number;
        chunkLength: number;
      };
    }
  | {
      event: 'finished';
      data: {
        downloadId: number;
      };
    };

const onEvent = new Channel<DownloadEvent>();
onEvent.onmessage = (message) => {
  console.log(`got download event ${message.event}`);
};

await invoke('download', {
  url: 'https://raw.githubusercontent.com/tauri-apps/tauri/dev/crates/tauri-schema-generator/schemas/config.schema.json',
  onEvent,
});
```

## Évaluer du JavaScript

Pour exécuter directement du code JavaScript dans le contexte de la webview, vous pouvez utiliser la fonction [`WebviewWindow#eval`] :

```rust title="src-tauri/src/lib.rs"
use tauri::Manager;

tauri::Builder::default()
  .setup(|app| {
    let webview = app.get_webview_window("main").unwrap();
    webview.eval("console.log('hello from Rust')")?;
    Ok(())
  })
```

Si le script à évaluer n'est pas aussi simple et doit utiliser des entrées provenant d'objets Rust, nous recommandons d'utiliser la crate [serialize-to-javascript].
