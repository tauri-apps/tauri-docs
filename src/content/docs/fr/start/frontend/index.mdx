Tauri est agnostique côté frontend et prend en charge la plupart des frameworks frontend prêts à l'emploi. Cependant, un framework peut parfois nécessiter un peu de configuration supplémentaire pour s'intégrer à Tauri. Vous trouverez ci-dessous une liste de frameworks avec les configurations recommandées.

Si un framework n'est pas listé, il peut fonctionner avec Tauri sans configuration supplémentaire, ou ne pas encore être documenté. Toute contribution visant à ajouter un framework qui pourrait nécessiter une configuration supplémentaire est bienvenue pour aider les autres membres de la communauté Tauri.

## Liste de contrôle de configuration

Conceptuellement, Tauri agit comme un hôte web statique. Vous devez fournir à Tauri un dossier contenant un mélange de HTML, CSS, JavaScript et éventuellement de WASM qui peut être servi à la webview fournie par Tauri.

Voici une liste de contrôle des scénarios courants nécessaires pour intégrer un frontend avec Tauri :

- Utilisez la génération de site statique (SSG), les applications monopages (SPA) ou les applications multipages classiques (MPA). Tauri ne prend pas nativement en charge les alternatives basées sur un serveur (comme SSR).
- Pour le développement mobile, un serveur de développement est nécessaire afin d'héberger le frontend sur votre IP interne.
- Utilisez une vraie relation client-serveur entre votre app et vos API (pas de solutions hybrides avec SSR).
