Tauri permet à votre app d'avoir une CLI via [clap](https://github.com/clap-rs/clap), un analyseur robuste d'arguments de ligne de commande. Avec une définition CLI simple dans votre fichier `tauri.conf.json`, vous pouvez définir votre interface et lire la map des correspondances d'arguments en JavaScript et/ou en Rust.

## Configuration de base

Sous `tauri.conf.json`, vous disposez de la structure suivante pour configurer l'interface :

```json title="src-tauri/tauri.conf.json"
{
  "plugins": {
    "cli": {
      "description": "Tauri CLI Plugin Example",
      "args": [
        {
          "short": "v",
          "name": "verbose",
          "description": "Verbosity level"
        }
      ],
      "subcommands": {
        "run": {
          "description": "Run the application",
          "args": [
            {
              "name": "debug",
              "description": "Run application in debug mode"
            },
            {
              "name": "release",
              "description": "Run application in release mode"
            }
          ]
        }
      }
    }
  }
}
```

:::note

Toutes les configurations JSON présentées ici ne sont que des exemples ; de nombreux autres champs ont été omis pour plus de clarté.

:::

## Ajouter des arguments

Le tableau `args` représente la liste des arguments acceptés par sa commande ou sous-commande.

{/* TODO: List available configuration */}

### Arguments positionnels

Un argument positionnel est identifié par sa position dans la liste des arguments. Avec la configuration suivante :

```json title="src-tauri/tauri.conf.json"
{
  "args": [
    {
      "name": "source",
      "index": 1,
      "takesValue": true
    },
    {
      "name": "destination",
      "index": 2,
      "takesValue": true
    }
  ]
}
```

Les utilisateurs peuvent lancer votre app avec `./app tauri.txt dest.txt` et la map des correspondances d'arguments définira `source` à `"tauri.txt"` et `destination` à `"dest.txt"`.

### Arguments nommés

Un argument nommé est une paire clé-valeur dans laquelle la clé identifie la valeur. Avec la configuration suivante :

```json title="tauri-src/tauri.conf.json"
{
  "args": [
    {
      "name": "type",
      "short": "t",
      "takesValue": true,
      "multiple": true,
      "possibleValues": ["foo", "bar"]
    }
  ]
}
```

Les utilisateurs peuvent lancer votre app avec `./app --type foo bar`, `./app -t foo -t bar` ou `./app --type=foo,bar`, et la map des correspondances d'arguments définira `type` à `["foo", "bar"]`.

### Arguments indicateurs

Un argument indicateur est une clé autonome dont la présence ou l'absence fournit des informations à votre application. Avec la configuration suivante :

```json title="tauri-src/tauri.conf.json"
{
  "args": [
    {
      "name": "verbose",
      "short": "v"
    }
  ]
}
```

Les utilisateurs peuvent lancer votre app avec `./app -v -v -v`, `./app --verbose --verbose --verbose` ou `./app -vvv`, et la map des correspondances d'arguments définira `verbose` à `true`, avec `occurrences = 3`.

## Sous-commandes

Certaines applications CLI possèdent des interfaces supplémentaires sous forme de sous-commandes. Par exemple, la CLI `git` possède `git branch`, `git commit` et `git push`. Vous pouvez définir d'autres interfaces imbriquées avec le tableau `subcommands` :

```json title="tauri-src/tauri.conf.json"
{
  "cli": {
    ...
    "subcommands": {
      "branch": {
        "args": []
      },
      "push": {
        "args": []
      }
    }
  }
}
```

Sa configuration est la même que celle de l'application racine, avec `description`, `longDescription`, `args`, etc.

## Utilisation

Le plugin CLI est disponible en JavaScript et en Rust.

<Tabs syncKey="lang">
  <TabItem label="JavaScript">

```javascript
import { getMatches } from '@tauri-apps/plugin-cli';
// when using `"withGlobalTauri": true`, you may use
// const { getMatches } = window.__TAURI__.cli;

const matches = await getMatches();
if (matches.subcommand?.name === 'run') {
  // `./your-app run $ARGS` was executed
  const args = matches.subcommand.matches.args;
  if (args.debug?.value === true) {
    // `./your-app run --debug` was executed
  }
  if (args.release?.value === true) {
    // `./your-app run --release` was executed
  }
}
```

  </TabItem>
  <TabItem label="Rust">

```rust title="src-tauri/src/lib.rs" {1, 6-18}
use tauri_plugin_cli::CliExt;

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
   tauri::Builder::default()
       .plugin(tauri_plugin_cli::init())
       .setup(|app| {
           match app.cli().matches() {
               // `matches` here is a Struct with { args, subcommand }.
               // `args` is `HashMap<String, ArgData>` where `ArgData` is a struct with { value, occurrences }.
               // `subcommand` is `Option<Box<SubcommandMatches>>` where `SubcommandMatches` is a struct with { name, matches }.
               Ok(matches) => {
                   println!("{:?}", matches)
               }
               Err(_) => {}
           }
           Ok(())
       })
       .run(tauri::generate_context!())
       .expect("error while running tauri application");
}
```

  </TabItem>

## Permissions

Par défaut, toutes les commandes et portées potentiellement dangereuses du plugin sont bloquées et ne sont pas accessibles. Vous devez modifier les permissions dans votre configuration `capabilities` pour les activer.

Consultez la [vue d'ensemble des capabilities](/fr/security/capabilities/) pour plus d'informations et le [guide pas à pas](/fr/learn/security/using-plugin-permissions/) pour utiliser les permissions des plugins.

```json title="src-tauri/capabilities/default.json" ins={6}
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "main-capability",
  "description": "Capability for the main window",
  "windows": ["main"],
  "permissions": ["cli:default"]
}
```
