Un application bundle est le format de paquet exécuté sur macOS. Il s'agit d'un simple répertoire qui inclut tout ce dont votre application a besoin pour fonctionner correctement,
y compris l'exécutable de votre app, les ressources, le fichier Info.plist et d'autres fichiers comme les frameworks macOS.

Pour empaqueter votre app sous forme d'application bundle macOS, vous pouvez utiliser la CLI Tauri et exécuter la commande `tauri build` sur un ordinateur Mac :

<CommandTabs
  npm="npm run tauri build -- --bundles app"
  yarn="yarn tauri build --bundles app"
  pnpm="pnpm tauri build --bundles app"
  deno="deno task tauri build --bundles app"
  bun="bun tauri build --bundles app"
  cargo="cargo tauri build --bundles app"
/>

:::note

Les apps GUI sur macOS et Linux n'héritent pas du `$PATH` de vos fichiers de configuration shell (`.bashrc`, `.bash_profile`, `.zshrc`, etc.). Consultez la crate [fix-path-env-rs](https://github.com/tauri-apps/fix-path-env-rs) de Tauri pour corriger ce problème.

:::

## Structure de fichiers

L'app bundle macOS est un répertoire avec la structure suivante :

```
├── <productName>.app
│   ├── Contents
│   │   ├── Info.plist
│   │   ├── ...additional files from [`tauri.conf.json > bundle > macOS > files`]
│   ├── MacOS
│   │   ├── <app-name> (app executable)
│   ├── Resources
│   │   ├── icon.icns (app icon)
│   │   ├── ...resources from [`tauri.conf.json > bundle > resources`]
│   ├── _CodeSignature (codesign information generated by Apple)
│   ├── Frameworks
│   ├── PlugIns
│   ├── SharedSupport
```

Consultez la [documentation officielle](https://developer.apple.com/library/archive/documentation/CoreFoundation/Conceptual/CFBundles/BundleTypes/BundleTypes.html) pour plus d'informations.

## Configuration native

L'app bundle est configuré par le fichier `Info.plist`, qui inclut des paires clé-valeur avec l'identité de votre app et les valeurs de configuration lues par macOS.

Tauri configure automatiquement les propriétés les plus importantes, comme le nom du binaire de votre app, sa version, son identifiant de bundle, sa version système minimale, et plus encore.

Pour étendre le fichier de configuration, créez un fichier `Info.plist` dans le dossier `src-tauri` et incluez les paires clé-valeur souhaitées :

```xml title="src-tauri/Info.plist"
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
	<key>NSCameraUsageDescription</key>
	<string>Request camera access for WebRTC</string>
	<key>NSMicrophoneUsageDescription</key>
	<string>Request microphone access for WebRTC</string>
</dict>
</plist>
```

Ce fichier `Info.plist` est fusionné avec les valeurs générées par la CLI Tauri. Soyez prudent lorsque vous remplacez des valeurs par défaut comme la version de l'application, car elles peuvent entrer en conflit avec d'autres valeurs de configuration
et introduire un comportement inattendu.

Consultez la [documentation officielle Info.plist] pour plus d'informations.

### Localisation de Info.plist

Le fichier `Info.plist` seul ne prend en charge qu'une seule langue, généralement l'anglais. Si vous voulez prendre en charge plusieurs langues, vous pouvez créer des fichiers `InfoPlist.strings` pour chaque langue supplémentaire. Chaque fichier appartient à son propre répertoire `lproj` spécifique à la langue dans le répertoire `Resources` de l'application bundle.

Pour empaqueter ces fichiers automatiquement, vous pouvez utiliser la fonctionnalité [resources] de Tauri. Pour cela, créez dans votre projet une structure de fichiers suivant ce modèle :

```
├── src-tauri
│   ├── tauri.conf.json
│   ├── infoplist
│   │   ├── de.lproj
│   │   │   ├── InfoPlist.strings
│   │   ├── fr.lproj
│   │   │   ├── InfoPlist.strings
```

Le nom du répertoire `infoplist` peut être choisi librement tant que vous le mettez à jour dans la configuration des resources ci-dessous, mais les répertoires `lproj` doivent suivre le nommage `<lang-code>.lproj` et les catalogues de chaînes doivent être nommés `InfoPlist.strings` (I et P majuscules). Dans la plupart des cas, le code de langue doit être un code à deux lettres suivant [BCP 47].

Pour l'exemple `Info.plist` ci-dessus, le fichier `de.lproj > InfoPlist.strings` pourrait ressembler à ceci :

```ini title="de.lproj/InfoPlist.strings"
NSCameraUsageDescription = "Kamera Zugriff wird benötigt für WebRTC Funktionalität";
NSMicrophoneUsageDescription = "Mikrofon Zugriff wird benötigt für WebRTC Funktionalität";
```

Enfin, faites en sorte que Tauri récupère ces fichiers en utilisant la fonctionnalité resources mentionnée plus haut :

```json title="src-tauri/tauri.conf.json"
{
  "bundle": {
    "resources": {
      "infoplist/**": "./"
    }
  }
}
```

## Entitlements

Un entitlement est une paire clé-valeur spéciale de configuration Apple qui agit comme un droit ou privilège accordant à votre app des capacités particulières,
comme agir en tant que client e-mail par défaut de l'utilisateur ou utiliser la fonctionnalité App Sandbox.

Les entitlements sont appliqués lorsque votre application est signée. Consultez la [documentation de signature du code] pour plus d'informations.

Pour définir les entitlements requis par votre application, vous devez créer le fichier d'entitlements et configurer Tauri pour l'utiliser.

1. Créez un fichier `Entitlements.plist` dans le dossier `src-tauri` et configurez les paires clé-valeur requises par votre app :

```xml title="src-tauri/Entitlements.plist"
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>com.apple.security.app-sandbox</key>
    <true/>
</dict>
</plist>
```

2. Configurez Tauri pour utiliser le fichier Entitlements.plist :

```json title="tauri.conf.json" ins={4}
{
  "bundle": {
    "macOS": {
      "entitlements": "./Entitlements.plist"
    }
  }
}
```

Consultez la [documentation officielle](https://developer.apple.com/documentation/bundleresources/entitlements) pour plus d'informations.

## Version système minimale

Par défaut, votre application Tauri prend en charge macOS 10.13 et supérieur. Si vous utilisez une API nécessitant un système macOS plus récent et voulez imposer cette exigence dans votre app bundle,
vous pouvez configurer la valeur [`tauri.conf.json > bundle > macOS > minimumSystemVersion`] :

```json title="tauri.conf.json" ins={4}
{
  "bundle": {
    "macOS": {
      "minimumSystemVersion": "12.0"
    }
  }
}
```

## Inclure des frameworks macOS

Si votre application nécessite des frameworks macOS supplémentaires pour s'exécuter, vous pouvez les lister dans la configuration [`tauri.conf.json > bundle > macOS > frameworks`].
La liste de frameworks peut inclure des frameworks système ou personnalisés, ainsi que des fichiers dylib.

```json title="tauri.conf.json" ins={4-8}
{
  "bundle": {
    "macOS": {
      "frameworks": [
        "CoreAudio",
        "./libs/libmsodbcsql.18.dylib",
        "./frameworks/MyApp.framework"
      ]
    }
  }
}
```

:::note

- Pour référencer un framework système, vous pouvez simplement utiliser son nom (sans l'extension .framework) au lieu d'un chemin absolu.
- Les frameworks système doivent exister dans `$HOME/Library/Frameworks`, `/Library/Frameworks/` ou `/Network/Library/Frameworks/`.
- Pour référencer des frameworks locaux et des fichiers dylib, vous devez utiliser le chemin complet vers le framework, relatif au répertoire `src-tauri`.

:::

## Ajouter des fichiers personnalisés

Vous pouvez utiliser la configuration [`tauri.conf.json > bundle > macOS > files`] pour ajouter des fichiers personnalisés à votre application bundle,
qui mappe le chemin de destination vers sa source relative au fichier `tauri.conf.json`.
Les fichiers sont ajoutés au dossier `<product-name>.app/Contents`.

```json title="tauri.conf.json" ins={4-7}
{
  "bundle": {
    "macOS": {
      "files": {
        "embedded.provisionprofile": "./profile-name.provisionprofile",
        "SharedSupport/docs.md": "./docs/index.md"
      }
    }
  }
}
```

Dans l'exemple ci-dessus, le fichier `profile-name.provisionprofile` est copié vers `<product-name>.app/Contents/embedded.provisionprofile`
et le fichier `docs/index.md` est copié vers `<product-name>.app/Contents/SharedSupport/docs.md`.
