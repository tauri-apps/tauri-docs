『[Tauri とは？](/ja/start/)』の章を通じてすべての設定を終えたのであれば、Tauri を使ってアプリケーションを実行できます。

「UI フレームワーク」または「JavaScript バンドラー」を使用している場合は、おそらく開発サーバーへのアクセスが可能で、あなたの開発プロセスが迅速化されます。それゆえ、アプリの「開発 URL」とそれを起動する「スクリプト」を設定していない場合は、『Reference（参考情報）』内の「Configuration／設定」の章にある [devUrl](/ja/reference/config/#devurl) および [beforeDevCommand](/ja/reference/config/#beforedevcommand) の設定値を利用して設定してください：

```json title=tauri.conf.json
{
  "build": {
    "devUrl": "http://localhost:3000",
    "beforeDevCommand": "npm run dev"
  }
}
```

:::note（注記）

どのフレームワークにもそれぞれ独自の開発ツールがあります。そのすべてを網羅したり、最新情報を紹介することは、このガイドの目的ではありません。

自分の選択したフレームワークの関連文書を参照して、その内容を学習し正しい設定値を確認してください。

:::

反対に、「UI フレームワーク」も「モジュール・バンドラー」も使用していない場合では、Tauri に「フロントエンド・ソース・コード」の場所を指定すると、Tauri CLI によって代わりの臨時開発サーバーが起動されます：

```json title=tauri.conf.json
{
  "build": {
    "frontendDist": "./src"
  }
}
```

上記の例では、`src` フォルダーには、フロントエンドによって読み込まれる他のアセットに加えて `index.html` ファイルが含まれていなければならない点に注意してください。

:::note[Windowsにおける絶対パス]

`frontendDist` は、URL またはパスのいずれかを受け入れます。`D:\dist` や `D:/dist` のような Windows の絶対パスは、「ディレクトリ」としてではなく「スキーム<sup>※</sup> `d` を持つ URL」として解釈されます。
絶対パスを使用するためには、「拡張長プレフィックス<sup>※</sup>」の `\\?\` を追加してください。`tauri.conf.json` 内では、バックスラッシュ（`\`）はすべてエスケープ（重ね書き `\\` に）する必要があります。

```json
"frontendDist": "\\\\?\\D:\\path\\to\\dist"
```

このプレフィックスを使用すると、Windows は `/` を正規化<sup>※</sup>しなくなるため、バックスラッシュのみを使用してください。`../dist` のような「相対パス」は通常どおり機能します。

:::

<TranslationNote lang="ja">

・**スキーム**　（scheme）：　リソースへアクセスための通信手段を示す識別子。例えば `https` は Web ページへのアクセス、`ftp` はファイル転送プロトコルを指定する識別子。<br />
・**拡張長プレフィックス**　（the extended-length prefix）：　Windows のファイルパス長制限を「拡張・延長」するために付加する接頭記号「`\\?\`」。<br />
・**正規化**　（normalize）：　通常 Windows ではスラッシュ（`/`）をバックスラッシュ（`\`）に自動変換しています（文字表記の「正規化」という）が、拡張長プレフィックスを指定すると書かれた通りの文字列として扱われます。《[参考](https://learn.microsoft.com/ja-jp/windows/win32/intl/using-unicode-normalization-to-represent-strings)》

</TranslationNote>

:::caution[基本開発サーバー<sup>※</sup>のセキュリティ]

Tauri の組み込み開発サーバーは「相互認証」や「暗号化」をサポートしていません。したがって、信頼できないネットワーク上での開発ではこのサーバーを決して使用しないでください。
詳細については、『アプリケーション・ライフサイクルでの脅威』の章の「[開発サーバーの項のセキュリティに関する考慮事項](/ja/security/lifecycle/#開発サーバー)」を参照してください。

:::

<TranslationNote lang="ja">

・**基本開発サーバー**　（plain/vanilla Dev Server）：　オプションやカスタマイズを一切含まない完全にデフォルト状態のサーバー。英文表記の plain/vanilla とは「簡素な、平凡な、ありきたりの」の意味。

</TranslationNote>

## デスクトップ・アプリケーションの開発

デスクトップ用のアプリケーションを開発するには、`tauri dev` コマンドを実行します。

<CommandTabs
  npm="npm run tauri dev"
  yarn="yarn tauri dev"
  pnpm="pnpm tauri dev"
  deno="deno task tauri dev"
  bun="bun tauri dev"
  cargo="cargo tauri dev"
/>

初めてこのコマンドを実行する場合、Rust パッケージ・マネージャーが必要なすべてのパッケージをダウンロードしてビルドするのに **数分** かかる場合があります。
これらのデータはキャッシュされており、あなたのコードは再ビルドを必要としているだけなので、その後のビルドは遥かに高速になります。

Rust がビルド処理を完了すると、WebView が開き、あなたの Web アプリが表示されます。
その Web アプリに変更を加えると、ツールがサポートしている場合には、まるでブラウザのように WebView も自動的に更新されるはずです。

### 「ウェブ・インスペクター」を開く

WebView を右クリックして「検査（Inspect）」項目を選択するか、ショートカットを使用することで（Windows および Linux では `Ctrl + Shift + I` 、macOS では `Cmd + Option + I` ）、アプリケーションをデバッグするための「ウェッブ・インスペクター」が開きます。

## モバイル・アプリケーションの開発

モバイル向けの開発はデスクトップ版の開発と似ていますが、（上述の `tauri dev` の代わりに）そのモバイルのプラットフォームに応じて `tauri android dev` または `tauri ios dev` を実行する必要があります：

<CommandTabs
  npm="npm run tauri [android|ios] dev"
  yarn="yarn tauri [android|ios] dev"
  pnpm="pnpm tauri [android|ios] dev"
  deno="deno task tauri [android|ios] dev"
  bun="bun tauri [android|ios] dev"
  cargo="cargo tauri [android|ios] dev"
/>

初めてこのコマンドを実行する場合、Rust パッケージ・マネージャーが必要なすべてのパッケージをダウンロードしてビルドするのに **数分** かかる場合があります。
これらのデータはキャッシュされており、あなたのコードは再ビルドを必要としているだけなので、その後のビルドは遥かに高速になります。

### 開発サーバー

モバイル用の開発サーバーもデスクトップ用と同様に動作しますが、「iOS の物理デバイス上」（実機）で実行しようとしている場合には、Tauri CLI が提示する特定のアドレス（環境変数の `TAURI_DEV_HOST` で定義されています）を応答待機（リッスン）するように設定する必要があります。
このアドレスは、「パブリック・ネットワークのアドレス」（デフォルト設定）または iOS 物理デバイス（実機）の「TUN アドレス」のいずれかです。後者はより安全ですが、現時点ではデバイスへの接続に「Xcode 統合開発環境」を必要とします。

iOS デバイスのアドレスを使用するには、「dev コマンド」を実行する前に Xcode を開き、「ウィンドウ（Window） > デバイスとシミュレータ（Devices and Simulation）」メニューでそのデバイスがネットワーク経由で接続されていることを確認しなければなりません。
その後、`tauri ios dev --force-ip-prompt` を実行し、iOS デバイスのアドレス（**::2** で終わる IPv6 アドレス）を選択する必要があります。

iOS デバイスからアクセス可能となるように、開発サーバーを正しいホストで応答待機（リッスン）させるには、「`TAURI_DEV_HOST` 値」が提供されている場合はその値を使用するように設定を微調整する必要があります。以下は Vite での設定例です：

```js
import { defineConfig } from 'vite';

const host = process.env.TAURI_DEV_HOST;

// https://vitejs.dev/config/
export default defineConfig({
  clearScreen: false,
  server: {
    host: host || false,
    port: 1420,
    strictPort: true,
    hmr: host
      ? {
          protocol: 'ws',
          host,
          port: 1421,
        }
      : undefined,
  },
});
```

詳細については、各フレームワークの「セットアップ・ガイド」を確認してください。

:::note（注記）

[create-tauri-app](https://github.com/tauri-apps/create-tauri-app) を用いて作成したプロジェクトでは、追加設定なしでそのまま使用可能なモバイル開発用の開発サーバーが設定されます。

:::

### デバイスの選択

デフォルトでは、「モバイル dev コマンド」は、接続されたデバイスでアプリケーションを実行しようとし、使用するシミュレータを選択するようプロンプトを表示します。実行ターゲットを事前に定義することで、「デバイス名」または「シミュレータ名」を引数に指定できます：

<CommandTabs
  npm="npm run tauri ios dev 'iPhone 15'"
  yarn="yarn tauri ios dev 'iPhone 15'"
  pnpm="pnpm tauri ios dev 'iPhone 15'"
  deno="deno task tauri ios dev 'iPhone 15'"
  bun="bun tauri ios dev 'iPhone 15'"
  cargo="cargo tauri ios dev 'iPhone 15'"
/>

### Xcode または Android Studio を使用する

あるいは、統合開発環境（IDE）の Xcode または Android Studio を使用してアプリケーションを開発することもできます。
これにより、コマンドライン・ツールの代わりに IDE を使用して、開発上の諸問題のトラブルシューティングを行なえるようになります。
接続されたデバイスやシミュレーター上で実行する代わりに、モバイル IDE を開くには、`--open` フラグを使用してください：

<CommandTabs
  npm="npm run tauri [android|ios] dev --open"
  yarn="yarn tauri [android|ios] dev --open"
  pnpm="pnpm tauri [android|ios] dev --open"
  deno="deno task tauri [android|ios] dev --open"
  bun="bun tauri [android|ios] dev --open"
  cargo="cargo tauri [android|ios] dev --open"
/>

:::note（注記）
アプリケーションを iOS 物理デバイス（実機）で実行する場合には、引数 `--host` も指定する必要があり、開発サーバー側ではホストとして `process.env.TAURI_DEV_HOST` を使用していなければなりません。
詳細については、各フレームワークの「セットアップ・ガイド」を確認してください。

<CommandTabs
  npm="npm run tauri [android|ios] dev --open --host"
  yarn="yarn tauri [android|ios] dev --open --host"
  pnpm="pnpm tauri [android|ios] dev --open --host"
  deno="deno task tauri [android|ios] dev --open --host"
  bun="bun tauri [android|ios] dev --open --host"
  cargo="cargo tauri [android|ios] dev --open --host"
/>
:::

:::caution（警告）

Xcode や Android Studio を使用するためには、「Tauri CLI」のプロセスが実行されて**いる必要があり**、Tauri CLI を強制終了しては**いけません**。
`tauri [android|ios] dev --open` コマンドを使用して、IDE を終了するまで Tauri CLI プロセスを維持することを推奨します。

:::

### 「ウェブ・インスペクター」を開く

- iOS

  iOS アプリケーションの「Web Inspector／ウェブ・インスペクター」にアクセスするには、Safari を使用する必要があります。

  Mac PC で Safari を開き、メニュー・バーで **Safari > Setting（設定）** を選択、**Advanced（詳細）** をクリックして、**Show features for web developers（Web 開発者向けの機能を表示）** を選択します。

  物理デバイス（実機）で実行している場合は、**Settings（設定） > Safari > Advanced（詳細）** で **Web Inspector（ウェブ・インスペクター）** を有効にする必要があります。

  すべての手順を実行すると、Safari に **Develop（開発）** メニューが表示され、その中に、検証すべき接続デバイスとアプリケーションが見つかります。
  デバイスまたはシミュレータを選択して **localhost（ローカルホスト）** をクリックすれば、「Safari 開発ツール」のウィンドウが開きます。

- Android

  「インスペクター」は Android エミュレーター向けにはデフォルトで有効になっていますが、物理デバイス（実機）向けには有効化する必要があります。
  Android デバイスをコンピューターに接続し、Android デバイス上の **Settings（設定）** アプリを開きます。**About（デバイス情報）** を選択し、「Build Number／ビルド番号」までスクロールし、その番号を七回タップします。
  これにより、Android デバイス用の「Developer Mode／開発者モード」と **Developer Options（開発者向けオプション）** 設定が有効になります。

  あなたのデバイスでアプリケーションのデバッグを有効にするには、**Developer Options（開発者向けオプション）** 設定に入り、開発者向けオプション・スイッチを切り替えて、**USB Debugging（USB デバッグ）** を有効化する必要があります。

  :::note（注記）

  「開発者モード」（開発者向けオプション）を有効化する方法は、Android ディストリビューションごとに異なります。詳細については、それぞれの製造元のドキュメントを確認してください。

  :::

  Android 用の「Web Inspector／ウェブ・インスペクター」は Google Chrome の DevTools を利用しており、コンピュータの Chrome ブラウザで `chrome://inspect` と検索するとアクセスできます。
  Android アプリケーションが実行中であれば、あなたのデバイスあるいはエミュレータが「リモート・デバイスのリスト」に表示されるはずで、そのデバイスに該当する項目の **inspect（検査）** をクリックすれば「DevTools／デベロッパーツール」を開くことができます。

### トラブル・シューティング

1. Xcode でのビルド・スクリプト実行エラー

Tauri は iOS の Xcode プロジェクトに割り込み処理（フック）を行ないますが、この割り込み処理は、Tauri CLI に「Rust のソースコードをランタイム時に読み込まれるライブラリとしてコンパイルさせる」処理を行なわせるビルド・フェーズを生成することで実現しています<sup>※</sup>。
このビルド・フェーズは「Xcode プロセス・コンテキスト」（Xcode 本体の実行プロセス）上で実行されるため、PATH の追加などといったシェルの修正を行なえない可能性があります。このため、「Node.js バージョン・マネージャー」などのツールを使用する場合は相性の問題があるかもしれませんので注意してください。

<TranslationNote lang="ja">

・**Tauri CLI に「Rust のソースコードを…**　　この一連の処理の背景には、iOS アプリが Rust のコードをそのまま実行できないため、そのコードを一旦ライブラリ化し iOS 側から呼び出すことで使用可能にする必要があるためです。

</TranslationNote>

2. iOS アプリの初回実行時にネットワーク許可を求めるプロンプト

初めて `tauri ios dev` を実行すると、iOS のメッセージが表示され、ローカル・ネットワーク上のデバイスを検索し接続するための許可を求められる場合があります。
この許可が必要とされるのは、iOS デバイスから開発サーバーにアクセスするために、開発サーバーがローカル・ネットワーク側から「見える状態（exposed）」になっている必要があるためです。
デバイス上でアプリを実行するには、「Allow（許可）」をクリックしてアプリケーションを再起動してください。

## ソースコードの変更への対応

WebView がリアルタイムで変更内容を反映するのと同様に、`tauri dev` もワークスペース内の `src-tauri` フォルダとその依存クレートの変化を監視しており、あなたが変更を行なうたびに、あなたのアプリケーションは自動的に再ビルドされて再起動されます。

この動作は、`tauri dev` コマンドに `--no-watch` フラグを使用すれば無効化できます。

特定のファイルが監視されない（ignore）ようにするには、`.taurignore` ファイルを作成します。このファイルは通常の「`.gitignore` ファイル」と同じように機能します：

```txt title=".taurignore"
build/
src/generated/*.rs
deny.toml
```

`.taurignore` ファイルは通常 `src-tauri` ディレクトリまたは [cargo workspace](https://doc.rust-lang.org/cargo/reference/workspaces.html) のルート・フォルダに置かれています。現時点では、`tauri dev` は、監視対象フォルダと Cargo ワークスペースのルート・フォルダの共通の親フォルダ<sup>※</sup>配下のどこかに `.taurignore` ファイルが存在していることを前提としています。

<TranslationNote lang="ja">

・**共通の親フォルダ**　（common ancestor＝共通の祖先フォルダ）：　階層構造であるディレクトリの中の「上位の」フォルダ（家系図の祖先・先祖と同じ考え方）。下位ののファイルから遡る際に（ここでは監視対象のフォルダーと Cargo ワークスペースのルート・フォルダー）、この二つのフォルダーの共通の上位フォルダを指します。

</TranslationNote>

## 「ブラウザ開発ツール」の使用

Tauri の API はアプリのウィンドウ内のみでしか機能しないため、一旦 Tauri API を使用し始めると、システム側のブラウザからはフロントエンドを開くことができなくなります。

もしブラウザの開発者ツールを利用して開発したい場合は、[tauri-invoke-http](https://github.com/tauri-apps/tauri-invoke-http) を設定して、Tauri API の呼び出しを HTTP サーバーを介してブリッジする必要があります。

## ソース管理

自分のプロジェクト・リポジトリで、`src-tauri/Cargo.toml` とともに `src-tauri/Cargo.lock` も git に**コミットする必要があります**。これは、Cargo が「決定論的なビルド<sup>※</sup>」を提供するためにロックファイル<sup>※</sup>を使用するからです。
そのため、すべてのアプリケーションでその `Cargo.lock` ファイルをチェックイン<sup>※</sup>することをお勧めします。`src-tauri/target` フォルダまたはその中のファイルは**コミットしてはいけません**。

<TranslationNote lang="ja">

・**ロックファイル**　（lockfile）：　プロジェクトで使用している外部ライブラリやパッケージの「正確なバージョン」と「依存関係」をすべて記録し、固定（ロック）するためのファイル（＝ Cargo.lock）。Cargo.toml にはアプリの基本設定が記載されているため、 ロックファイルと対で必要。<br />
・**決定論的なビルド**　（deterministic builds）：　deterministic とは「アルゴリズムに決定性があり、次のステップが常に（確定的に）一つに決まること」、すなわち、「同じソースコードを用いてコンパイルした場合、確実に同じバイナリデータを再現するビルド手法」のことをいいます（詳しくは、Wikipedia 「[再現性のあるビルド](https://ja.wikipedia.org/wiki/再現性のあるビルド)／Reproducible builds」を参照してください）。<br />
・**チェックイン**　（check in）：　Gitなどのバージョン管理システム（リポジトリ）にコミットする操作。

</TranslationNote>
