Разрешения — это описания явных привилегий команд.

```toml
[[permission]]
identifier = "my-identifier"
description = "This describes the impact and more."
commands.allow = [
    "read_file"
]

[[permission.scope.allow]]
my-scope = "$HOME/*"

[[permission.scope.deny]]
my-scope = "$HOME/secret"
```

Они могут делать команды доступными во фронтенде приложения Tauri.
Они могут сопоставлять области с командами и определяют, какие команды включены.
Разрешения могут включать или запрещать определённые команды, определять области или сочетать и то и другое.

Чтобы предоставить или запретить разрешение окну или webview вашего приложения,
вы должны указать разрешение в [возможности](/ru/security/capabilities/).

Разрешения можно группировать в набор под новым идентификатором.
Это называется набором разрешений. Это позволяет вам сочетать разрешения, связанные с областями,
с разрешениями, связанными с командами. Это также позволяет группировать или объединять операционные
специфичные разрешения в более удобные наборы.

Как разработчик плагина вы можете поставлять несколько предопределённых, хорошо названных разрешений
для всех ваших открытых команд.

Как разработчик приложения вы можете расширять существующие разрешения плагинов или
определять их для собственных команд.
Их можно группировать или расширять в наборе для переиспользования или для упрощения основных
файлов конфигурации впоследствии.

## Идентификатор разрешения

Идентификатор разрешения используется для обеспечения того, что разрешения можно переиспользовать и что они имеют уникальные имена.

:::tip

Под **именем** мы подразумеваем имя крейта плагина без префикса `tauri-plugin-`.
Это задумано как неймспейсинг для снижения вероятности конфликтов имён.
При указании разрешений самого приложения это не обязательно.

:::

- `<name>:default` Указывает, что разрешение является разрешением по умолчанию для плагина или приложения
- `<name>:<command-name>` Указывает, что разрешение предназначено для отдельной команды

Префикс плагина `tauri-plugin-` будет автоматически добавляться к идентификатору плагинов
на этапе компиляции, и его не требуется указывать вручную.

Идентификаторы ограничены строчными буквенными символами ASCII `[a-z]`, а максимальная длина
идентификатора в настоящее время ограничена `116` из-за следующих констант:

```rust
const IDENTIFIER_SEPARATOR: u8 = b':';
const PLUGIN_PREFIX: &str = "tauri-plugin-";

// https://doc.rust-lang.org/cargo/reference/manifest.html#the-name-field
const MAX_LEN_PREFIX: usize = 64 - PLUGIN_PREFIX.len();
const MAX_LEN_BASE: usize = 64;
const MAX_LEN_IDENTIFIER: usize = MAX_LEN_PREFIX + 1 + MAX_LEN_BASE;
```

## Файлы конфигурации

Упрощённый пример структуры каталогов **плагина** Tauri:

```sh
tauri-plugin
├── README.md
├── src
│  └── lib.rs
├── build.rs
├── Cargo.toml
├── permissions
│  └── <identifier>.json/toml
│  └── default.json/toml
```

Разрешение по умолчанию обрабатывается особым образом,
поскольку оно автоматически добавляется в конфигурацию
приложения, если CLI Tauri используется для
добавления плагинов в приложение Tauri.

Для разработчиков **приложений** структура похожа:

```sh
tauri-app
├── index.html
├── package.json
├── src
├── src-tauri
│   ├── Cargo.toml
│   ├── permissions
│      └── <identifier>.toml
|   ├── capabilities
│      └── <identifier>.json/.toml
│   ├── src
│   ├── tauri.conf.json
```

:::note

Как разработчик приложения вы можете писать файлы возможностей в `json`/`json5` или `toml`,
тогда как разрешения можно определять только в `toml`.

:::

## Примеры

Примеры разрешений из плагина `File System`.

```toml title="plugins/fs/permissions/autogenerated/base-directories/home.toml"
[[permission]]
identifier = "scope-home"
description = """This scope permits access to all files and
list content of top level directories in the `$HOME`folder."""

[[permission.scope.allow]]
path = "$HOME/*"
```

```toml title="plugins/fs/permissions/read-files.toml"
[[permission]]
identifier = "read-files"
description = """This enables all file read related
commands without any pre-configured accessible paths."""
commands.allow = [
    "read_file",
    "read",
    "open",
    "read_text_file",
    "read_text_file_lines",
    "read_text_file_lines_next"
]
```

```toml title="plugins/fs/permissions/autogenerated/commands/mkdir.toml"
[[permission]]
identifier = "allow-mkdir"
description = "This enables the mkdir command."
commands.allow = [
    "mkdir"
]
```

Пример реализации, расширяющей вышеуказанные разрешения плагина в вашем приложении:

```toml title="my-app/src-tauri/permissions/home-read-extends.toml"
[[set]]
identifier = "allow-home-read-extended"
description = """ This allows non-recursive read access to files and to create directories
in the `$HOME` folder.
"""
permissions = [
    "fs:read-files",
    "fs:scope-home",
    "fs:allow-mkdir"
]
```
