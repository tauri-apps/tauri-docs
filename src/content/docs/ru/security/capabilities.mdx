Tauri предоставляет разработчикам приложений и плагинов систему возможностей (capabilities),
чтобы детально включать и ограничивать доступ ядра к фронтенду приложения, работающему в
системном WebView.

Возможности определяют, какие [разрешения](/ru/security/permissions/)
предоставляются или запрещаются для каких окон или webview.

Возможности могут затрагивать несколько окон и webview, и эти окна/webview могут быть
указаны в нескольких возможностях.

:::tip[Совет по безопасности]

Окна и WebView, которые входят более чем в одну возможность,
фактически объединяют границы безопасности и разрешения всех
участвующих возможностей.

:::

Файлы возможностей определяются либо как файл JSON, либо как файл TOML
внутри каталога `src-tauri/capabilities`.

Хорошей практикой является использование отдельных файлов и ссылка на них
только по идентификатору в `tauri.conf.json`, но также возможно
определить их напрямую в поле `capabilities`.

Все возможности внутри каталога `capabilities` автоматически включаются
по умолчанию.
Как только возможности явно включены в `tauri.conf.json`,
в сборке приложения используются только они.

Для полного справочника схемы конфигурации обратитесь к разделу
[ссылки](/reference/config/).

Следующий пример JSON определяет возможность, которая позволяет главному окну
использовать функциональность по умолчанию основных плагинов и API `window.setTitle`.

```json title="src-tauri/capabilities/default.json"
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "main-capability",
  "description": "Capability for the main window",
  "windows": ["main"],
  "permissions": [
    "core:path:default",
    "core:event:default",
    "core:window:default",
    "core:app:default",
    "core:resources:default",
    "core:menu:default",
    "core:tray:default",
    "core:window:allow-set-title"
  ]
}
```

Эти фрагменты являются частью файла
[конфигурации Tauri](/ru/develop/configuration-files/#конфигурация-tauri).

Это, вероятно, самый распространённый метод конфигурации,
где отдельные возможности встраиваются инлайн, и только
разрешения упоминаются по идентификатору.

Это требует хорошо определённых
файлов возможностей в каталоге `capabilities`.

```json title=src-tauri/tauri.conf.json
{
  "app": {
    "security": {
      "capabilities": ["my-capability", "main-capability"]
    }
  }
}
```

Инлайн-возможности можно смешивать с предопределёнными возможностями.

```json title=src-tauri/tauri.conf.json
{
  "app": {
    "security": {
      "capabilities": [
        {
          "identifier": "my-capability",
          "description": "My application capability used for all windows",
          "windows": ["*"],
          "permissions": ["fs:default", "allow-home-read-extended"]
        },
        "my-second-capability"
      ]
    }
  }
}
```

По умолчанию всем командам, которые вы зарегистрировали в своём приложении
(с помощью функции
[`tauri::Builder::invoke_handler`](https://docs.rs/tauri/2.0.0/tauri/struct.Builder.html#method.invoke_handler)),
разрешено использоваться всеми окнами и webview приложения.
Чтобы изменить это, рассмотрите использование
[`AppManifest::commands`](https://docs.rs/tauri-build/2.0.0/tauri_build/struct.AppManifest.html#method.commands).

```rust title=src-tauri/build.rs
fn main() {
    tauri_build::try_build(
        tauri_build::Attributes::new()
            .app_manifest(tauri_build::AppManifest::new().commands(&["your_command"])),
    )
    .unwrap();
}
```

## Целевая платформа

Возможности могут быть специфичны для платформы путём определения массива `platforms`.
По умолчанию возможность применяется ко всем целевым платформам,
но вы можете выбрать подмножество целей `linux`, `macOS`, `windows`, `iOS` и `android`.

Например, возможность для настольных операционных систем.
Обратите внимание: она включает разрешения на плагинах, которые доступны только на настольных системах:

```json title="src-tauri/capabilities/desktop.json"
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "desktop-capability",
  "windows": ["main"],
  "platforms": ["linux", "macOS", "windows"],
  "permissions": ["global-shortcut:allow-register"]
}
```

И ещё один пример возможности для мобильных устройств.
Обратите внимание: она включает разрешения на плагинах, которые доступны только на мобильных устройствах:

```json title="src-tauri/capabilities/mobile.json"
{
  "$schema": "../gen/schemas/mobile-schema.json",
  "identifier": "mobile-capability",
  "windows": ["main"],
  "platforms": ["iOS", "android"],
  "permissions": [
    "nfc:allow-scan",
    "biometric:allow-authenticate",
    "barcode-scanner:allow-scan"
  ]
}
```

## Удалённый доступ к API

По умолчанию API доступен только для кода, поставляемого вместе с приложением Tauri.
Чтобы разрешить удалённым источникам доступ к определённым командам Tauri, это можно определить
в файле конфигурации возможностей.

Этот пример позволил бы сканировать NFC-метки и использовать сканер штрихкодов со
всех поддоменов `tauri.app`.

```json title="src-tauri/capabilities/remote-tags.json"
{
  "$schema": "../gen/schemas/remote-schema.json",
  "identifier": "remote-tag-capability",
  "windows": ["main"],
  "remote": {
    "urls": ["https://*.tauri.app"]
  },
  "platforms": ["iOS", "android"],
  "permissions": ["nfc:allow-scan", "barcode-scanner:allow-scan"]
}
```

:::caution

На Linux и Android Tauri не может различить запросы от встроенного `<iframe>` и самого окна.

Пожалуйста, внимательно рассмотрите использование этой функции и прочитайте подробнее о конкретных
последствиях безопасности для вашей целевой операционной системы в разделе ссылок этой функции.

:::

## Границы безопасности

_От чего она защищает?_

В зависимости от разрешений и возможностей она способна:

- Минимизировать последствия компрометации фронтенда
- Предотвращать или снижать (случайное) раскрытие локальных системных интерфейсов и данных
- Предотвращать или снижать возможную эскалацию привилегий от фронтенда к бэкенду/системе

_От чего она **не** защищает?_

- Злонамеренный или небезопасный код на Rust
- Слишком слабые области и конфигурацию
- Некорректные проверки области в реализации команды
- Преднамеренные обходы из кода на Rust
- По сути всё, что было написано в ядре приложения на Rust
- 0-дней или неисправленные 1-дни в системном WebView
- Атаки на цепочку поставок или иным образом скомпрометированные системы разработчиков

:::tip[Совет по безопасности]

Границы безопасности зависят от меток окон (**не заголовков**).
Мы рекомендуем открывать функциональность создания окон
только для окон с более высокими привилегиями.

:::

## Файлы схем

Tauri генерирует JSON-схемы со всеми разрешениями, доступными
вашему приложению, через `tauri-build`, что позволяет осуществлять автодополнение в вашей IDE.
Чтобы использовать схему, задайте свойство `$schema` в вашем файле конфигурации
(либо .json, либо .toml) равным одной из платформо-специфичных схем,
расположенных в каталоге `gen/schemas`. Обычно
вы зададите его равным `../gen/schemas/desktop-schema.json` или
`../gen/schemas/mobile-schema.json`, хотя вы также можете определить возможность
для конкретной целевой платформы.

## Файлы конфигурации

Упрощённый пример структуры каталогов примера приложения Tauri:

```sh
tauri-app
├── index.html
├── package.json
├── src/
├── src-tauri/
│   ├── Cargo.toml
│   ├── capabilities/
│   │  └── <identifier>.json/toml
│   ├── src/
│   ├── tauri.conf.json
```

Всё можно встроить инлайн в `tauri.conf.json`, но даже
немного более продвинутая конфигурация раздула бы этот файл, и
цель такого подхода — чтобы разрешения были абстрагированы
везде, где возможно, и просты для понимания.
