Межпроцессное взаимодействие (IPC) позволяет изолированным процессам безопасно общаться и является ключом к созданию более сложных приложений.

Tauri использует особый стиль межпроцессного взаимодействия, называемый [Асинхронная передача сообщений], где процессы обмениваются _запросами_ и _ответами_, сериализованными с помощью некоторого простого представления данных. Передача сообщений должна звучать знакомо для любого, у кого есть опыт веб-разработки, поскольку эта парадигма используется для связи клиент-сервер в интернете.

Передача сообщений — более безопасная техника, чем общая память или прямой доступ к функциям, потому что получатель волен отклонять или отбрасывать запросы по своему усмотрению. Например, если основной процесс Tauri Core определяет, что запрос злонамерен, он просто отбрасывает запрос и никогда не выполняет соответствующую функцию.

Далее мы более подробно объясним два IPC-примитива Tauri — `Events` и `Commands`.

## Events

Events — это сообщения IPC в стиле «выстрелил и забыл», односторонние, которые лучше всего подходят для передачи событий жизненного цикла и изменений состояния. В отличие от [Commands](#commands), Events могут испускаться как Фронтендом, _так и_ ядром Tauri Core.

Под капотом events всё равно используют Commands, а доступ к API events контролируется [правами Event](/reference/acl/core-permissions/#event).

## Commands

Tauri также предоставляет абстракцию в стиле [интерфейса внешних функций] поверх IPC-сообщений[^1]. Основной API, `invoke`, похож на браузерный API `fetch` и позволяет Фронтенду вызывать функции Rust, передавать аргументы и получать данные.

Поскольку этот механизм под капотом использует протокол в стиле [JSON-RPC] для сериализации запросов и ответов, все аргументы и возвращаемые данные должны быть сериализуемы в JSON.
