Паттерн Isolation — это способ перехватывать и изменять сообщения API Tauri, отправляемые фронтендом, до того как они попадут в ядро Tauri Core, — и всё это на JavaScript. Безопасный код JavaScript, который внедряется паттерном Isolation, называется приложением Isolation.

## Зачем

Цель паттерна Isolation — предоставить механизм, который помогает разработчикам защитить своё приложение от нежелательных или злонамеренных вызовов фронтенда к ядру Tauri Core. Необходимость в паттерне Isolation возникла из-за угроз, исходящих от недоверенного контента, работающего во фронтенде, — распространённый случай для приложений со множеством зависимостей. См. [Безопасность: модели угроз] для списка многих источников угроз, с которыми может столкнуться приложение.

Крупнейшая модель угроз, описанная выше, для которой проектировался паттерн Isolation, — это угрозы разработки. Не только многие инструменты фронтенда на этапе сборки состоят из десятков (или сотен) часто глубоко вложенных зависимостей, но и сложное приложение может иметь большое количество (также часто глубоко вложенных) зависимостей, которые включаются в итоговый вывод.

## Когда

Tauri настоятельно рекомендует использовать паттерн Isolation везде, где это возможно. Поскольку приложение Isolation перехватывает _**все**_ сообщения от фронтенда, его _всегда_ можно использовать.

Tauri также настоятельно советует ограничивать ваше приложение при использовании внешних API Tauri. Как разработчик, вы можете использовать безопасное приложение Isolation, чтобы пытаться проверять IPC-входы, убеждаясь, что они находятся в рамках ожидаемых параметров. Например, вы можете захотеть проверить, что вызов чтения или записи файла не пытается получить доступ к пути за пределами ожидаемых расположений вашего приложения. Другой пример — убедиться, что вызов HTTP-загрузки через API Tauri устанавливает заголовок Origin только в то значение, которое ожидает ваше приложение.

Тем не менее, оно перехватывает _**все**_ сообщения от фронтенда, поэтому будет работать даже с постоянно включёнными API, такими как [Events]. Поскольку некоторые события могут вызывать выполнение действий вашим собственным кодом на Rust, с ними можно использовать те же методы проверки.

## Как

Паттерн Isolation заключается во внедрении безопасного приложения между вашим фронтендом и ядром Tauri Core для перехвата и изменения входящих IPC-сообщений. Он делает это, используя функцию песочницы `<iframe>` для безопасного выполнения JavaScript рядом с основным приложением фронтенда. Tauri применяет паттерн Isolation при загрузке страницы, заставляя все IPC-вызовы к ядру Tauri Core сначала маршрутизироваться через изолированное в песочнице приложение Isolation. Когда сообщение готово к передаче в ядро Tauri Core, оно шифруется с помощью реализации [SubtleCrypto] браузера и передаётся обратно в основное приложение фронтенда. Затем оно напрямую передаётся в ядро Tauri Core, где расшифровывается и читается как обычно.

Чтобы гарантировать, что кто-то не сможет вручную прочитать ключи для конкретной версии вашего приложения и использовать их для изменения сообщений после шифрования, новые ключи генерируются при каждом запуске вашего приложения.

### Приблизительные шаги IPC-сообщения

Чтобы было легче следить, вот упорядоченный список с приблизительными шагами, которые проходит IPC-сообщение при отправке в ядро Tauri Core с паттерном Isolation:

1. Обработчик IPC Tauri получает сообщение
2. Обработчик IPC -> приложение Isolation
3. `[sandbox]` Хук приложения Isolation запускается и потенциально изменяет сообщение
4. `[sandbox]` Сообщение шифруется с помощью AES-GCM, используя ключ, сгенерированный во время выполнения
5. `[encrypted]` Приложение Isolation -> обработчик IPC
6. `[encrypted]` Обработчик IPC -> ядро Tauri Core

_Примечание: Стрелки (->) обозначают передачу сообщений._

### Влияние на производительность

Поскольку шифрование сообщения действительно происходит, есть дополнительные накладные расходы по сравнению с [паттерном Brownfield], даже если безопасное приложение Isolation ничего не делает. Помимо приложений, чувствительных к производительности (которые, вероятно, имеют тщательно поддерживаемый и небольшой набор зависимостей для поддержания адекватной производительности), большинство приложений не должны замечать затраты времени выполнения на шифрование/расшифровку IPC-сообщений, поскольку они относительно малы, а AES-GCM относительно быстр. Если вы не знакомы с AES-GCM, всё, что важно в этом контексте, — это то, что это единственный алгоритм с режимом аутентификации, включённый в [SubtleCrypto], и что вы, вероятно, уже используете его каждый день под капотом с [TLS][transport_layer_security].

Также каждый раз при запуске приложения Tauri генерируется криптографически безопасный ключ. Обычно это незаметно, если в системе достаточно энтропии для немедленного возврата нужного количества случайных чисел, что крайне распространено для настольных сред. Если вы работаете в среде без головы для выполнения [интеграционного тестирования с WebDriver], вам, возможно, захочется установить какую-нибудь службу генерации энтропии, например `haveged`, если ваша операционная система не включает её. <sup>Linux 5.6 (март 2020) теперь включает генерацию энтропии с использованием спекулятивного выполнения.</sup>

### Ограничения

В паттерне Isolation есть несколько ограничений, возникших из-за несоответствий платформ. Самое значительное ограничение связано с тем, что внешние файлы неправильно загружаются внутри изолированных `<iframes>` на Windows. Из-за этого мы реализовали простой шаг инлайнинга скриптов на этапе сборки, который берёт содержимое скриптов относительно приложения Isolation и внедряет их инлайн. Это означает, что обычная бандлизация или простое включение файлов вроде `<script src="index.js"></script>` по-прежнему работает правильно, но более новые механизмы, такие как ES-модули, _не_ будут успешно загружаться.

## Рекомендации

Поскольку смысл приложения Isolation — защита от угроз разработки, мы настоятельно рекомендуем держать ваше приложение Isolation как можно более простым. Вы должны не только стремиться минимизировать зависимости вашего приложения Isolation, но и рассмотреть возможность минимизации его необходимых шагов сборки. Это позволит вам не беспокоиться об атаках на цепочку поставок против вашего приложения Isolation в дополнение к вашему приложению фронтенда.

## Создание приложения Isolation

В этом примере мы создадим маленькое приложение Isolation в стиле hello-world и подключим его к воображаемому существующему приложению Tauri. Оно не будет выполнять никакой проверки проходящих через него сообщений, а только выводить их содержимое в консоль WebView.

Для целей этого примера представим, что мы находимся в том же каталоге, что и `tauri.conf.json`. Существующее приложение Tauri имеет своё `frontendDist`, установленное в `../dist`.

`../dist-isolation/index.html`:

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>Isolation Secure Script</title>
  </head>
  <body>
    <script src="index.js"></script>
  </body>
</html>
```

`../dist-isolation/index.js`:

```javascript
window.__TAURI_ISOLATION_HOOK__ = (payload) => {
  // давайте ничего не проверять и не изменять, просто выведем содержимое из хука
  console.log('hook', payload);
  return payload;
};
```

Теперь всё, что нам нужно сделать, — настроить наш `tauri.conf.json` [конфигурацию](#конфигурация) на использование паттерна Isolation — и мы перешли с [паттерна Brownfield] на паттерн Isolation.

## Конфигурация

Предположим, что `frontendDist` нашего основного фронтенда установлен в `../dist`. Мы также выводим наше приложение Isolation в `../dist-isolation`.

```json
{
  "build": {
    "frontendDist": "../dist"
  },
  "app": {
    "security": {
      "pattern": {
        "use": "isolation",
        "options": {
          "dir": "../dist-isolation"
        }
      }
    }
  }
}
```
