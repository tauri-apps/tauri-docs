Теперь, когда у вас [всё настроено](/ru/start/), вы готовы запустить своё приложение с помощью Tauri.

Если вы используете UI-фреймворк или сборщик JavaScript, скорее всего, у вас есть доступ к серверу разработки,
который ускорит ваш процесс разработки, поэтому, если вы ещё не настроили URL разработки вашего приложения и скрипт,
который его запускает, вы можете сделать это через значения конфигурации [devUrl](/reference/config/#devurl) и
[beforeDevCommand](/reference/config/#beforedevcommand):

```json title=tauri.conf.json
{
  "build": {
    "devUrl": "http://localhost:3000",
    "beforeDevCommand": "npm run dev"
  }
}
```

:::note

У каждого фреймворка есть свой инструментарий для разработки. Рассмотреть их все или поддерживать в актуальном состоянии — вне рамок этого документа.

Пожалуйста, обратитесь к документации вашего фреймворка, чтобы узнать больше и определить правильные значения для настройки.

:::

В противном случае, если вы не используете UI-фреймворк или сборщик модулей, вы можете указать Tauri исходный код вашего фронтенда,
и CLI Tauri запустит сервер разработки для вас:

```json title=tauri.conf.json
{
  "build": {
    "frontendDist": "./src"
  }
}
```

Обратите внимание, что в этом примере папка `src` должна содержать файл `index.html`, а также любые другие ресурсы, загружаемые вашим фронтендом.

:::caution[Безопасность простого/ванильного сервера разработки]

Встроенный сервер разработки Tauri не поддерживает взаимную аутентификацию
и шифрование. Вам никогда не следует использовать его для разработки в недоверенных сетях.
Подробное объяснение см. в разделе [соображения безопасности сервера разработки](/ru/security/lifecycle/#dev-сервер).

:::

## Разработка настольного приложения

Чтобы разрабатывать приложение для настольных платформ, выполните команду `tauri dev`.

<CommandTabs
  npm="npm run tauri dev"
  yarn="yarn tauri dev"
  pnpm="pnpm tauri dev"
  deno="deno task tauri dev"
  bun="bun tauri dev"
  cargo="cargo tauri dev"
/>

При первом запуске этой команды менеджер пакетов Rust может потратить **несколько минут** на загрузку и сборку всех необходимых пакетов.
Поскольку они кэшируются, последующие сборки выполняются гораздо быстрее: пересобирать нужно только ваш код.

Когда Rust завершит сборку, откроется webview, отображающий ваше веб-приложение.
Вы можете вносить изменения в веб-приложение, и если ваш инструментарий это поддерживает, webview должен обновляться автоматически, как браузер.

### Открытие инспектора Web

Вы можете открыть инспектор Web для отладки приложения, щёлкнув правой кнопкой мыши по webview и выбрав "Inspect" (осмотреть) или
используя сочетание клавиш `Ctrl + Shift + I` в Windows и Linux или `Cmd + Option + I` в macOS.

## Разработка мобильного приложения

Разработка под мобильные платформы аналогична настольной, но вместо этого нужно выполнять `tauri android dev` или `tauri ios dev`:

<CommandTabs
  npm="npm run tauri [android|ios] dev"
  yarn="yarn tauri [android|ios] dev"
  pnpm="pnpm tauri [android|ios] dev"
  deno="deno task tauri [android|ios] dev"
  bun="bun tauri [android|ios] dev"
  cargo="cargo tauri [android|ios] dev"
/>

При первом запуске этой команды менеджер пакетов Rust может потратить **несколько минут** на загрузку и сборку всех необходимых пакетов.
Поскольку они кэшируются, последующие сборки выполняются гораздо быстрее: пересобирать нужно только ваш код.

### Сервер разработки

Сервер разработки на мобильных платформах работает аналогично настольному, но если вы пытаетесь запустить приложение на физическом устройстве iOS,
вам необходимо настроить его на прослушивание определённого адреса, предоставляемого CLI Tauri и заданного в переменной окружения `TAURI_DEV_HOST`.
Этот адрес является либо публичным адресом сети (поведение по умолчанию), либо фактическим TUN-адресом устройства iOS — что более безопасно, но в настоящее время
требует Xcode для подключения к устройству.

Чтобы использовать адрес устройства iOS, вы должны открыть Xcode перед запуском команды разработки и убедиться, что ваше устройство
подключено по сети в меню Window > Devices and Simulators.
Затем нужно выполнить `tauri ios dev --force-ip-prompt`, чтобы выбрать адрес устройства iOS (IPv6-адрес, оканчивающийся на **::2**).

Чтобы ваш сервер разработки прослушивал правильный хост и был доступен устройству iOS, вы должны подправить его конфигурацию
так, чтобы он использовал значение `TAURI_DEV_HOST`, если оно было задано. Вот пример конфигурации для Vite:

```js
import { defineConfig } from 'vite';

const host = process.env.TAURI_DEV_HOST;

// https://vite-docs.ru/config/
export default defineConfig({
  clearScreen: false,
  server: {
    host: host || false,
    port: 1420,
    strictPort: true,
    hmr: host
      ? {
          protocol: 'ws',
          host,
          port: 1421,
        }
      : undefined,
  },
});
```

Обратитесь к руководству по настройке вашего фреймворка для получения дополнительной информации.

:::note
Проекты, созданные с помощью [create-tauri-app](https://github.com/tauri-apps/create-tauri-app), настраивают
ваш сервер разработки для мобильной разработки «из коробки».
:::

### Выбор устройства

По умолчанию команда мобильной разработки пытается запустить приложение на подключённом устройстве,
а если это не удаётся — предлагает выбрать симулятор.
Чтобы заранее определить цель запуска, вы можете передать имя устройства или симулятора в качестве аргумента:

<CommandTabs
  npm="npm run tauri ios dev 'iPhone 15'"
  yarn="yarn tauri ios dev 'iPhone 15'"
  pnpm="pnpm tauri ios dev 'iPhone 15'"
  deno="deno task tauri ios dev 'iPhone 15'"
  bun="bun tauri ios dev 'iPhone 15'"

/>

### Использование Xcode или Android Studio

В качестве альтернативы вы можете выбрать использование Xcode или Android Studio для разработки вашего приложения.
Это может помочь устранить некоторые проблемы разработки, используя IDE вместо инструментов командной строки.
Чтобы открыть мобильную IDE вместо запуска на подключённом устройстве или симуляторе, используйте флаг `--open`:

<CommandTabs
  npm="npm run tauri [android|ios] dev --open"
  yarn="yarn tauri [android|ios] dev --open"
  pnpm="pnpm tauri [android|ios] dev --open"
  deno="deno task tauri [android|ios] dev --open"
  bun="bun tauri [android|ios] dev --open"
  cargo="cargo tauri [android|ios] dev --open"
/>

:::note
Если вы собираетесь запускать приложение на физическом устройстве iOS, вы также должны передать аргумент `--host`,
а ваш сервер разработки должен использовать значение `process.env.TAURI_DEV_HOST` в качестве хоста.
Обратитесь к руководству по настройке вашего фреймворка для получения дополнительной информации.

<CommandTabs
  npm="npm run tauri [android|ios] dev --open --host"
  yarn="yarn tauri [android|ios] dev --open --host"
  pnpm="pnpm tauri [android|ios] dev --open --host"
  deno="deno task tauri [android|ios] dev --open --host"
  bun="bun tauri [android|ios] dev --open --host"
  cargo="cargo tauri [android|ios] dev --open --host"
/>
:::

:::caution
Чтобы использовать Xcode или Android Studio, процесс CLI Tauri **обязан** работать и его **нельзя** завершать.
Рекомендуется использовать команду `tauri [android|ios] dev --open` и держать процесс запущенным, пока вы не закроете IDE.
:::

### Открытие инспектора Web

- iOS

  Для доступа к инспектору Web вашего приложения iOS необходимо использовать Safari.

  Откройте Safari на вашем Mac, выберите **Safari > Settings** в строке меню, нажмите **Advanced**, затем выберите **Show features for web developers**.

  Если вы работаете на физическом устройстве, вы должны включить **Web Inspector** в **Settings > Safari > Advanced**.

  После выполнения всех шагов в Safari должно появиться меню **Develop**, где вы найдёте подключённые устройства и приложения для проверки.
  Выберите ваше устройство или симулятор и нажмите на **localhost**, чтобы открыть окно инструментов разработчика Safari.

- Android

  Для эмуляторов Android инспектор включён по умолчанию, но для физических устройств его необходимо включить.
  Подключите устройство Android к компьютеру, откройте приложение **Settings** на устройстве Android, выберите **About**, прокрутите до Build Number и нажмите на него 7 раз.
  Это включит режим разработчика для вашего устройства Android и настройки **Developer Options**.

  Чтобы включить отладку приложения на вашем устройстве, вам необходимо войти в настройки **Developer Options**, включить переключатель параметров разработчика
  и включить **USB Debugging**.

  :::note
  У каждого дистрибутива Android свой способ включения режима разработчика. Пожалуйста, обратитесь к документации производителя вашего устройства за дополнительной информацией.
  :::

  Инспектор Web для Android работает на базе DevTools из Google Chrome, и к нему можно получить доступ, перейдя по адресу `chrome://inspect` в браузере Chrome на вашем компьютере.
  Ваше устройство или эмулятор появится в списке удалённых устройств, если ваше приложение Android запущено, и вы можете открыть инструменты разработчика,
  нажав **inspect** на записи, соответствующей вашему устройству.

### Устранение неполадок

1. Ошибка запуска скрипта сборки в Xcode

Tauri подключается к iOS-проекту Xcode, создавая фазу сборки, которая выполняет CLI Tauri для компиляции исходного кода Rust
как библиотеки, загружаемой во время выполнения. Фаза сборки выполняется в контексте процесса Xcode, поэтому она может быть не в состоянии
использовать изменения оболочки, такие как добавление в PATH, поэтому будьте осторожны при использовании таких инструментов, как менеджеры версий Node.js, которые могут быть несовместимы.

2. Запрос разрешения сети при первом запуске приложения iOS

При первом выполнении `tauri ios dev` iOS может запросить разрешение на поиск и подключение
к устройствам в вашей локальной сети. Это разрешение требуется, потому что для доступа к серверу разработки с устройства iOS
он должен быть доступен в локальной сети. Чтобы запустить приложение на устройстве, вы должны нажать Allow (разрешить) и перезапустить приложение.

## Реакция на изменения исходного кода

Подобно тому, как ваш webview отражает изменения в реальном времени,
`tauri dev` отслеживает изменения в вашей папке `src-tauri` и зависимых крейтах в рабочем пространстве,
поэтому ваше приложение автоматически пересобирается и перезапускается всякий раз, когда вы их изменяете.

Вы можете отключить это поведение, используя флаг `--no-watch` в команде `tauri dev`.

Чтобы игнорировать отслеживание определённых файлов, вы можете создавать файлы `.taurignore`, которые работают как обычные файлы `.gitignore`:

```txt title=".taurignore"
build/
src/generated/*.rs
deny.toml
```

Файлы `.taurignore` обычно помещаются в каталог `src-tauri` или корневую папку [рабочего пространства Cargo](https://doc.rust-lang.org/cargo/reference/workspaces.html).
В настоящее время `tauri dev` ищет файлы `.taurignore` в любом месте внутри общего предка отслеживаемых папок и корневой папки рабочего пространства Cargo.

## Использование DevTools браузера

API Tauri работают только в окне вашего приложения, поэтому, как только вы начнёте их использовать, вы больше не сможете открывать свой фронтенд в браузере вашей системы.

Если вы предпочитаете использовать инструменты разработчика браузера, вы должны настроить [tauri-invoke-http](https://github.com/tauri-apps/tauri-invoke-http)
для передачи вызовов API Tauri через HTTP-сервер.

## Контроль версий

В репозитории вашего проекта вы **ДОЛЖНЫ** коммитить файл `src-tauri/Cargo.lock` вместе с `src-tauri/Cargo.toml` в git,
потому что Cargo использует lock-файл для обеспечения детерминированных сборок. В результате рекомендуется, чтобы все приложения включали
в репозиторий свой `Cargo.lock`. Вам **НЕ СЛЕДУЕТ** коммитить папку `src-tauri/target` или любое её содержимое.
