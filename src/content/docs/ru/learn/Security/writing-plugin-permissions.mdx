Цель этого упражнения — получить лучшее понимание того, как
разрешения плагинов можно создавать при написании собственного плагина.

В конце вы будете уметь создавать простые разрешения для
ваших плагинов.
У вас будет пример плагина Tauri, где разрешения частично автогенерируются,
а частично создаются вручную.

<Steps>

1. ### Создание плагина Tauri

    В нашем примере мы воспользуемся CLI Tauri [`cli`](/reference/cli/),
    чтобы создать структуру исходного кода плагина Tauri.
    Убедитесь, что вы установили все [Предварительные требования](/ru/start/prerequisites/),
    и проверьте, что у вас установлена CLI Tauri правильной версии,
    выполнив `cargo tauri info`.

    Вывод должен указывать, что версия `tauri-cli` — `2.x`.
    Мы продолжим это пошаговое объяснение с `pnpm`, но вы можете выбрать другой
    менеджер пакетов и заменить его в командах соответствующим образом.

    Когда у вас установлена свежая версия, вы можете
    приступить к созданию плагина с помощью CLI Tauri.

    <ShowSolution text="Показать решение">
    ```sh
    mkdir -p tauri-learning
    cd tauri-learning
    cargo tauri plugin new test
    cd tauri-plugin-test
    pnpm install
    pnpm build
    cargo build
    ```
    </ShowSolution>

2. ### Создание новой команды

    Чтобы продемонстрировать что-то практичное и простое, предположим,
    что наша команда записывает пользовательский ввод в файл в нашей временной папке, добавляя
    при этом некоторый пользовательский заголовок в файл.

    Давайте назовём нашу команду `write_custom_file`, реализуем её в `src/commands.rs`
    и добавим её в конструктор нашего плагина, чтобы она была доступна frontend.

    Основные утилиты Tauri автогенерируют разрешения `allow` и `deny` для этой
    команды, поэтому нам не нужно об этом заботиться.

    <ShowSolution text="Показать решение">

    Реализация команды:

    ```rust title="src/commands.rs" ins={15-22} ins=", Manager"
    use tauri::{AppHandle, command, Runtime};

    use crate::models::*;
    use crate::Result;
    use crate::TestExt;

    #[command]
    pub(crate) async fn ping<R: Runtime>(
        app: AppHandle<R>,
        payload: PingRequest,
    ) -> Result<PingResponse> {
        app.test1().ping(payload)
    }

    #[command]
    pub(crate) async fn write_custom_file<R: Runtime>(
        user_input: String,
        app: AppHandle<R>,
    ) -> Result<String> {
        std::fs::write(app.path().temp_dir().unwrap(), user_input)?;
        Ok("success".to_string())
    }

    ```

    Автогенерация встроенных разрешений для вашей новой команды:

    ```rust title="src/build.rs" ins="\"write_custom_file\""
    const COMMANDS: &[&str] = &["ping", "write_custom_file"];
    ```

    Эти встроенные разрешения будут автоматически сгенерированы системой сборки Tauri
    и будут видны в папке `permissions/autogenerated/commands`.
    По умолчанию будет создано разрешение `enable-<command>` и `deny-<command>`.

    </ShowSolution>
3. ### Предоставление новой команды

    Предыдущий шаг заключался в написании фактической реализации команды.
    Далее мы хотим предоставить её frontend, чтобы её можно было использовать.

    <ShowSolution text="Показать решение">

    Настройте конструктор Tauri для генерации invoke handler, чтобы передавать запросы IPC
    frontend только что реализованной команде:

    ```rust title="src/lib.rs"  ins="commands::write_custom_file,"
    pub fn init<R: Runtime>() -> TauriPlugin<R> {
    Builder::new("test")
        .invoke_handler(tauri::generate_handler![
            commands::ping,
            commands::write_custom_file,
        ])
        .setup(|app, api| {
            #[cfg(mobile)]
            let test = mobile::init(app, api)?;
            #[cfg(desktop)]
            let test = desktop::init(app, api)?;
            app.manage(test);

            // manage state so it is accessible by the commands
            app.manage(MyState::default());
            Ok(())
        })
        .build()
    }
    ```

    Предоставьте новую команду в модуле frontend.

    Этот шаг необходим для того, чтобы примерное приложение могло успешно
    импортировать модуль frontend. Это сделано для удобства и не
    влияет на безопасность, поскольку handler команды уже сгенерирован,
    и команду можно вызывать из frontend вручную.

    ```ts title="guest-js/index.ts" ins={11-13}
    import { invoke } from '@tauri-apps/api/core'

    export async function ping(value: string): Promise<string | null> {
      return await invoke<{value?: string}>('plugin:test|ping', {
        payload: {
          value,
        },
      }).then((r) => (r.value ? r.value : null));
    }

    export async function writeCustomFile(user_input: string): Promise<string> {
     return await invoke('plugin:test|write_custom_file',{userInput: user_input});
    }
    ```

    :::tip
    Параметр invoke должен быть в CamelCase. В этом примере это `userInput` вместо `user_input`.
    :::

    Убедитесь, что ваш пакет собран:

    ```
    pnpm build
    ```

    </ShowSolution>

4. ### Определение разрешений по умолчанию плагина

    Поскольку наш плагин должен предоставлять команду `write_custom_file` по умолчанию,
    мы должны добавить её в наше разрешение `default.toml`.

    <ShowSolution text="Показать решение">
    Добавьте это в наш набор разрешений по умолчанию, чтобы разрешить новую команду,
    которую мы только что предоставили.

    ```toml title="permissions/default.toml" ins=", \"allow-write-custom-file\""
    "$schema" = "schemas/schema.json"
    [default]
    description = "Default permissions for the plugin"
    permissions = ["allow-ping", "allow-write-custom-file"]
    ```
    </ShowSolution>

5. ### Вызов тестовой команды из примерного приложения

    Созданная структура каталогов плагина содержит папку `examples/tauri-app`,
    в которой есть готовое к использованию приложение Tauri для тестирования плагина.

    Поскольку мы добавили новую команду, нам нужно немного изменить frontend,
    чтобы вызывать вместо этого нашу новую команду.

    <ShowSolution text="Показать решение">
    ```svelte title="src/App.svelte" del={11-13,42-45} ins={14-16,45-49}
    <script>
      import Greet from './lib/Greet.svelte'
      import { ping, writeCustomFile } from 'tauri-plugin-test-api'

      let response = ''

      function updateResponse(returnValue) {
        response += `[${new Date().toLocaleTimeString()}]` + (typeof returnValue === 'string' ? returnValue : JSON.stringify(returnValue)) + '<br>'
      }

      function _ping() {
        ping("Pong!").then(updateResponse).catch(updateResponse)
      }
      function _writeCustomFile() {
        writeCustomFile("HELLO FROM TAURI PLUGIN").then(updateResponse).catch(updateResponse)
      }
    </script>

    <main class="container">
      <h1>Welcome to Tauri!</h1>

      <div class="row">
        <a href="https://vite-docs.ru" target="_blank">
          <img src="/vite.svg" class="logo vite" alt="Vite Logo" />
        </a>
        <a href="https://tauri.app" target="_blank">
          <img src="/tauri.svg" class="logo tauri" alt="Tauri Logo" />
        </a>
        <a href="https://svelte.dragomano.ru" target="_blank">
          <img src="/svelte.svg" class="logo svelte" alt="Svelte Logo" />
        </a>
      </div>

      <p>
        Click on the Tauri, Vite, and Svelte logos to learn more.
      </p>

      <div class="row">
        <Greet />
      </div>

      <div>
        <button on:click="{_ping}">Ping</button>
        <div>{@html response}</div>
      </div>
      <div>
        <button on:click="{_writeCustomFile}">Write</button>
        <div>{@html response}</div>
      </div>


    </main>

    <style>
      .logo.vite:hover {
        filter: drop-shadow(0 0 2em #747bff);
      }

      .logo.svelte:hover {
        filter: drop-shadow(0 0 2em #ff3e00);
      }
    </style>
    ```

    Запустив это и нажав кнопку «Write», вы должны увидеть следующее:

    ```
    success
    ```

    И вы должны найти файл `test.txt` в вашей временной папке, содержащий сообщение
    от нашей новой реализованной команды плагина.
    🥳

    </ShowSolution>
