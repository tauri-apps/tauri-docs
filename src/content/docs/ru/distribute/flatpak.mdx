## Отправка в Flathub
**_1. Сделайте форк [репозитория Flathub](https://github.com/flathub/flathub/fork)_**

**_2. Клонируйте форк_**

```shell
git clone --branch=new-pr git@github.com:your_github_username/flathub.git
````

**_3. Войдите в репозиторий_**

```shell
cd flathub
```

**_4. Создайте новую ветку_**

```shell
git checkout -b your_app_name
```

**_5. Откройте пул-реквест в ветку `new-pr` на GitHub_**

**_6. Ваше приложение теперь пройдёт процесс рецензирования, в рамках которого вас могут попросить внести изменения в проект._**

Подробную информацию о том, как работает Flatpak, можно получить в статье [Building your first Flatpak](https://docs.flatpak.org/en/latest/first-build.html)

Это руководство предполагает, что вы хотите распространять свой Flatpak через [Flathub](https://flathub.org/) — наиболее часто используемую платформу для распространения Flatpak. Если вы планируете использовать другие платформы, обратитесь к их документации.

## Предварительные требования

Чтобы протестировать приложение внутри среды выполнения Flatpak, вы можете сначала собрать Flatpak локально перед загрузкой приложения в Flathub. Это также может быть полезно, если вы хотите быстро поделиться сборками для разработки.

**1. Установите `flatpak` и `org.flatpak.Builder`**

Для локальной сборки Flatpak вам нужен `flatpak` из менеджера пакетов вашего дистрибутива:

<Tabs syncKey="distro">
  <TabItem label="Debian">

```sh
sudo apt install flatpak
```

  </TabItem>
  <TabItem label="Arch">

```sh
sudo pacman -S --needed flatpak
```

  </TabItem>
  <TabItem label="Fedora">

```sh
sudo dnf install flatpak
```

  </TabItem>
  <TabItem label="Gentoo">

```sh
sudo emerge --ask sys-apps/flatpak
```

  </TabItem>
</Tabs>

Затем установите упакованный как Flatpak `flatpak-builder` из Flathub вместо собственного пакета `flatpak-builder` вашего дистрибутива (это позволяет избежать проблем с упаковкой в дистрибутиве и включает `flatpak-builder-lint` для проверок готовности к Flathub):

```shell
flatpak install flathub org.flatpak.Builder
```

**2. Установите среду выполнения Flatpak**

```shell
flatpak install flathub org.gnome.Platform//51 org.gnome.Sdk//51
```

**3. [Соберите .deb вашего tauri-app](/reference/config/#bundleconfig)**

**4. [Создайте файл AppStream MetaInfo](https://www.freedesktop.org/software/appstream/metainfocreator/#/guiapp)**

**5. Создайте flatpak-манифест**

```yaml
# flatpak-builder.yaml
id: <identifier>

runtime: org.gnome.Platform
runtime-version: '51'
sdk: org.gnome.Sdk

command: <main_binary_name>
finish-args:
  - --socket=wayland # Permission needed to show the window
  - --socket=fallback-x11 # Permission needed to show the window
  - --device=dri # OpenGL, not necessary for all projects
  - --share=ipc
  - --talk-name=org.kde.StatusNotifierWatcher # Optional: needed only if your app uses the tray icon
  - --filesystem=xdg-run/tray-icon:create # Optional: needed only if your app uses the tray icon - see an alternative way below
  # - --env=WEBKIT_DISABLE_COMPOSITING_MODE=1 # Optional: may solve some issues with black webviews on Wayland

modules:
  - name: binary
    buildsystem: simple

    sources:
      # A reference to the previously generated flatpak metainfo file
      - type: file
        path: flatpak.metainfo.xml
      # If you use GitHub releases, you can target an existing remote file
      - type: file
        url: https://github.com/your_username/your_repository/releases/download/v1.0.1/yourapp_1.0.1_amd64.deb
        sha256: 08305b5521e2cf0622e084f2b8f7f31f8a989fc7f407a7050fa3649facd61469 # This is required if you are using a remote source
        only-arches: [x86_64] # This source is only used on x86_64 Computers
      # You can also use a local file for testing
      # - type: file
      #   path: yourapp_1.0.1_amd64.deb
    build-commands:
      - set -e

      # Extract the deb package
      - mkdir deb-extract
      - ar -x *.deb --output deb-extract
      - tar -C deb-extract -xf deb-extract/data.tar.gz

      # Copy binary
      - 'install -Dm755 deb-extract/usr/bin/<executable_name> /app/bin/<executable_name>'

      # If you bundle files with additional resources, you should copy them:
      - mkdir -p /app/lib/<product_name>
      - cp -r deb-extract/usr/lib/<product_name>/. /app/lib/<product_name>
      - find /app/lib/<product_name> -type f -exec chmod 644 {} \;

      # Copy desktop file + ensure the right icon is set
      - sed -i 's/^Icon=.*/Icon=<identifier>/' deb-extract/usr/share/applications/<product_name>.desktop
      - install -Dm644 deb-extract/usr/share/applications/<product_name>.desktop /app/share/applications/<identifier>.desktop

      # Copy icons
      - install -Dm644 deb-extract/usr/share/icons/hicolor/128x128/apps/<main_binary_name>.png /app/share/icons/hicolor/128x128/apps/<identifier>.png
      - install -Dm644 deb-extract/usr/share/icons/hicolor/32x32/apps/<main_binary_name>.png /app/share/icons/hicolor/32x32/apps/<identifier>.png
      - install -Dm644 deb-extract/usr/share/icons/hicolor/256x256@2/apps/<main_binary_name>.png /app/share/icons/hicolor/256x256@2/apps/<identifier>.png
      - install -Dm644 flatpak.metainfo.xml /app/share/metainfo/<identifier>.metainfo.xml
```

Среда выполнения Gnome 51 включает все зависимости стандартного приложения Tauri с их правильными версиями.

:::note[Использование tray-icon без изменения Flatpak-манифеста]
Если вы предпочитаете не открывать доступ из приложения к $XDG_RUNTIME_DIR (где на Linux сохраняется tray-icon), вы можете изменить путь, по которому tauri сохраняет изображение трея:

```rust
# use tauri::{tray::TrayIconBuilder, Manager};
# fn setup(app: &mut tauri::App) {
TrayIconBuilder::new()
  .icon(app.default_window_icon().unwrap().clone())
  .temp_dir_path(app.path().app_cache_dir().unwrap()) // will save to the cache folder ($XDG_CACHE_HOME) where the app already has permission
  .build(app)
  .unwrap();
# }
```

:::

**5. Установите и протестируйте приложение**

```shell

# Install the flatpak
flatpak run org.flatpak.Builder --force-clean --user --disable-cache --repo flatpak-repo flatpak flatpak-builder.yaml

# Optional: check your manifest for Flathub readiness
flatpak run --command=flatpak-builder-lint org.flatpak.Builder manifest flatpak-builder.yaml

# Run it
flatpak run <your flatpak id> # or via your desktop environment

# Update it
flatpak -y --user update <your flatpak id>
```

## Добавление дополнительных библиотек

Если вашему итоговому бинарному файлу требуется больше библиотек, чем стандартному приложению tauri, вам нужно добавить их в ваш flatpak-манифест. Есть два способа сделать это. Для быстрой локальной разработки может сработать простое включение уже собранного файла библиотеки (`.so`) из вашей локальной системы. Однако это не рекомендуется для финальной сборки flatpak, так как ваш локальный файл библиотеки не собран для среды выполнения flatpak. Это может привести к различным ошибкам, которые очень трудно найти. Поэтому рекомендуется собирать библиотеку, от которой зависит ваша программа, из исходников внутри flatpak в качестве шага сборки.

## Отправка в Flathub

**_1. Сделайте форк [репозитория Flathub](https://github.com/flathub/flathub/fork)_**

**_2. Клонируйте форк_**

```shell
git clone --branch=new-pr git@github.com:your_github_username/flathub.git
```

**_3. Войдите в репозиторий_**

```shell
cd flathub
```

**_4. Создайте новую ветку_**

```shell
git checkout -b your_app_name
```

**_5. Добавьте манифест вашего приложения в ветку. Зафиксируйте изменения и затем отправьте их._**

**_6. Откройте пул-реквест в ветку `new-pr` на GitHub_**

**_7. Ваше приложение теперь пройдёт процесс рецензирования, в рамках которого вас могут попросить внести изменения в проект._**

Когда ваш пул-реквест будет одобрен, вы получите приглашение редактировать репозиторий вашего приложения. С этого момента вы сможете постоянно обновлять своё приложение.

Подробнее об этом можно прочитать [в документации flatpak](https://docs.flatpak.org/en/latest/dependencies.html#bundling)
