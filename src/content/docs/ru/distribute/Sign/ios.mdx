Подпись кода на iOS требуется для распространения вашего приложения через официальный [Apple App Store] или, возможно, альтернативные маркетплейсы в Европейском союзе, а также для установки и запуска на устройствах конечных пользователей.

## Предварительные требования

Подпись кода на iOS требует регистрации в программе [Apple Developer], которая на момент написания стоит 99$ в год. Вам также нужно устройство Apple, на котором вы выполняете подпись кода. Это требуется процессом подписи и обусловлено условиями и положениями Apple.

Чтобы распространять приложения iOS, вы должны иметь идентификатор бандла, зарегистрированный в App Store Connect, соответствующий сертификат подписи кода iOS и профиль мобильной подготовки (mobile provisioning), который связывает их вместе и включает возможности iOS, используемые вашим приложением. Эти требования могут либо автоматически управляться Xcode, либо предоставляться вручную.

## Автоматическая подпись

Позволить Xcode управлять подписью и подготовкой для вашего приложения — наиболее удобный способ экспортировать приложение iOS для распространения. Он автоматически регистрирует идентификатор бандла, управляет изменениями возможностей iOS и настраивает соответствующий сертификат в зависимости от вашего метода экспорта.

Автоматическая подпись включена по умолчанию и использует учётную запись, настроенную в Xcode, для аутентификации при использовании на вашем локальном компьютере.\ Чтобы зарегистрировать учётную запись, откройте приложение Xcode и страницу Settings в меню `Xcode > Settings`, переключитесь на вкладку Accounts и нажмите значок `+`.

Чтобы использовать автоматическую подпись на платформах CI/CD, вы должны создать ключ API App Store Connect и задать переменные окружения `APPLE_API_ISSUER`, `APPLE_API_KEY` и `APPLE_API_KEY_PATH`.\ Откройте [страницу Users and Access в App Store Connect][App Store Connect's Users and Access page], выберите вкладку Integrations, нажмите кнопку Add и выберите имя и доступ Admin. `APPLE_API_ISSUER` (Issuer ID) отображается над таблицей ключей, а `APPLE_API_KEY` — значение в столбце Key ID этой таблицы. Вам также необходимо загрузить закрытый ключ, что можно сделать только один раз, и он виден только после перезагрузки страницы (кнопка отображается в строке таблицы для только что созданного ключа). Путь к файлу закрытого ключа должен быть задан через переменную окружения `APPLE_API_KEY_PATH`.

## Ручная подпись

Чтобы подписать приложение iOS вручную, вы можете предоставить сертификат и профиль мобильной подготовки через переменные окружения:

- **IOS_CERTIFICATE**: представление в base64 сертификата, экспортированного из Keychain.
- **IOS_CERTIFICATE_PASSWORD**: пароль сертификата, заданный при экспорте из Keychain.
- **IOS_MOBILE_PROVISION**: представление в base64 профиля подготовки.

Следующие разделы объясняют, как получить эти значения.

### Сертификат подписи

После регистрации перейдите на страницу [Certificates], чтобы создать новый сертификат Apple Distribution. Скачайте новый сертификат и установите его в macOS Keychain.

Чтобы экспортировать ключ сертификата, откройте приложение «Keychain Access», разверните запись сертификата, щёлкните правой кнопкой мыши по элементу ключа и выберите пункт «Export \<key-name\>». Выберите путь к экспортированному файлу .p12 и запомните его пароль.

Выполните следующую команду `base64`, чтобы преобразовать сертификат в base64 и скопировать его в буфер обмена:

```
base64 -i <path-to-certificate.p12> | pbcopy
```

Значение в буфере обмена теперь является представлением подписывающего сертификата в base64. Сохраните его и используйте как значение переменной окружения `IOS_CERTIFICATE`.

Пароль сертификата должен быть задан в переменной `IOS_CERTIFICATE_PASSWORD`.

:::tip[Выбор типа сертификата]
Для каждого метода экспорта необходимо использовать соответствующий тип сертификата:

- **debugging**: Apple Development или iOS App Development
- **app-store-connect**: Apple Distribution или iOS Distribution (App Store Connect и Ad Hoc)
- **ad-hoc**: Apple Distribution или iOS Distribution (App Store Connect и Ad Hoc)

:::

### Профиль подготовки

Кроме того, вы должны предоставить профиль подготовки для вашего приложения. На странице [Identifiers](https://developer.apple.com/account/resources/identifiers/list) создайте новый App ID и убедитесь, что его значение «Bundle ID» совпадает с идентификатором, заданным в конфигурации [`identifier`].

Перейдите на страницу [Profiles](https://developer.apple.com/account/resources/profiles/list), чтобы создать новый профиль подготовки. Для распространения через App Store это должен быть профиль «App Store Connect». Выберите подходящий App ID и привяжите ранее созданный сертификат.

После создания профиля подготовки скачайте его и выполните следующую команду `base64`, чтобы преобразовать профиль и скопировать его в буфер обмена:

```
base64 -i <path-to-profile.mobileprovision> | pbcopy
```

Значение в буфере обмена теперь является представлением профиля подготовки в base64. Сохраните его и используйте как значение переменной окружения `IOS_MOBILE_PROVISION`.

Теперь вы можете собрать ваше приложение iOS и распространить его в App Store!
