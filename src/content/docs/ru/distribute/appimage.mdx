`AppImage` — это формат распространения, который не полагается на установленные в системе пакеты, а вместо этого включает все зависимости и файлы, необходимые приложению. По этой причине выходной файл больше, но его легче распространять, поскольку он поддерживается во многих дистрибутивах Linux и может выполняться без установки. Пользователю достаточно сделать файл исполняемым (`chmod a+x MyProject.AppImage`), после чего запустить его (`./MyProject.AppImage`).

AppImages удобны и упрощают процесс распространения, если вы не можете создать пакет для менеджера пакетов дистрибутива. Тем не менее, используйте их с осторожностью, так как размер файла вырастает с диапазона 2–6 МБ до 70+ МБ.

:::note

GUI-приложения на macOS и Linux не наследуют `$PATH` из ваших dotfiles оболочки (`.bashrc`, `.bash_profile`, `.zshrc` и т. д.). Ознакомьтесь с крейтом [fix-path-env-rs](https://github.com/tauri-apps/fix-path-env-rs) от Tauri, чтобы исправить эту проблему.

:::

## Ограничения

Ключевые библиотеки, такие как glibc, часто нарушают совместимость со старыми системами. Поэтому вы должны собирать своё приложение Tauri, используя самую старую базовую систему, которую планируете поддерживать и которая также предоставляет требуемые WebKitGTK 4.1 пакеты Tauri v2. Ubuntu 22.04 и Debian 12 являются подходящими примерами базовых систем, поскольку они предоставляют `libwebkit2gtk-4.1-dev` из своих стандартных репозиториев пакетов. Сборка на более новой базовой системе может повысить минимальную требуемую версию glibc, поэтому при запуске на более старой системе вы можете столкнуться с ошибкой времени выполнения, например `/usr/lib/libc.so.6: version 'GLIBC_2.33' not found`. Мы рекомендуем использовать контейнер Docker или GitHub Actions для сборки приложения Tauri для Linux.

Подробнее см. проблемы [tauri-apps/tauri#1355](https://github.com/tauri-apps/tauri/issues/1355) и [rust-lang/rust#57497](https://github.com/rust-lang/rust/issues/57497), а также [руководство по AppImage](https://docs.appimage.org/reference/best-practices.html#binaries-compiled-on-old-enough-base-system).

## Поддержка мультимедиа через GStreamer

Если ваше приложение воспроизводит аудио/видео, вам необходимо включить `tauri.conf.json > bundle > linux > appimage > bundleMediaFramework`. Это увеличит размер бандла AppImage, включив дополнительные файлы gstreamer, необходимые для воспроизведения медиа. В настоящее время этот флаг полностью поддерживается только в системах сборки на основе Ubuntu. Убедитесь, что ваша система сборки содержит все плагины, которые могут понадобиться вашему приложению во время выполнения.

:::caution

Плагины GStreamer из пакета `ugly` имеют лицензии, которые могут затруднить их распространение в составе вашего приложения.

## Собственные файлы

Чтобы включить в AppImage собственные файлы, которые вы не хотите включать через функцию [`resources`](/ru/develop/resources/) от Tauri, вы можете указать список файлов или папок в `tauri.conf.json > bundle > linux > appimage > files`. Объект конфигурации сопоставляет путь внутри AppImage с путём к файлу в вашей файловой системе относительно файла `tauri.conf.json`. Вот пример конфигурации:

```json title="tauri.conf.json"
{
  "bundle": {
    "linux": {
      "appimage": {
        "files": {
          "/usr/share/README.md": "../README.md", // copies the ../README.md file to <appimage>/usr/share/README.md
          "/usr/assets": "../assets/" // copies the entire ../assets directory to <appimage>/usr/assets
        }
      }
    }
  }
}
```

:::note

Обратите внимание, что пути назначения в настоящее время должны начинаться с `/usr/`.

:::

## AppImages для устройств на базе ARM

:::note[Обновление августа 2025]
GitHub [выпустил](https://github.blog/changelog/2025-08-07-arm64-hosted-runners-for-public-repositories-are-now-generally-available/#get-started) общедоступные раннеры `ubuntu-22.04-arm` и `ubuntu-24.04-arm`. Вы можете использовать их для сборки вашего приложения без изменений, обычная сборка должна занимать ~10 минут.
:::

`linuxdeploy`, инструмент AppImage, который использует Tauri, в настоящее время [не поддерживает кросс-компиляцию] ARM AppImages. Это означает, что ARM AppImages можно собирать только на устройствах ARM или эмуляторах.

Ознакомьтесь с нашим [руководством по GitHub Action](/ru/distribute/pipelines/github/#компиляция-на-arm-раннере), где приведён пример рабочего процесса, использующего QEMU для сборки приложения. Обратите внимание, что это чрезвычайно медленно и рекомендуется только в публичных репозиториях, где минуты сборки бесплатны. В частных репозиториях ARM-раннеры GitHub должны быть более экономичными и гораздо проще в настройке.

[не поддерживает кросс-компиляцию]: https://github.com/linuxdeploy/linuxdeploy/issues/258
