Бандл приложения — это формат пакета, который выполняется на macOS. Это простая директория, включающая всё необходимое для успешной работы вашего приложения: исполняемый файл приложения, ресурсы, файл Info.plist и другие файлы, такие как фреймворки macOS.

Чтобы упаковать приложение как бандл приложения macOS, вы можете использовать CLI Tauri и выполнить команду `tauri build` на компьютере Mac:

<CommandTabs
  npm="npm run tauri build -- --bundles app"
  yarn="yarn tauri build --bundles app"
  pnpm="pnpm tauri build --bundles app"
  deno="deno task tauri build --bundles app"
  bun="bun tauri build --bundles app"
  cargo="cargo tauri build --bundles app"
/>

:::note

GUI-приложения на macOS и Linux не наследуют `$PATH` из ваших dotfiles оболочки (`.bashrc`, `.bash_profile`, `.zshrc` и т. д.). Ознакомьтесь с крейтом [fix-path-env-rs](https://github.com/tauri-apps/fix-path-env-rs) от Tauri, чтобы исправить эту проблему.

:::

## Структура файлов

Бандл приложения macOS — это директория со следующей структурой:

```
├── <productName>.app
│   ├── Contents
│   │   ├── Info.plist
│   │   ├── ...additional files from [`tauri.conf.json > bundle > macOS > files`]
│   ├── MacOS
│   │   ├── <app-name> (app executable)
│   ├── Resources
│   │   ├── icon.icns (app icon)
│   │   ├── ...resources from [`tauri.conf.json > bundle > resources`]
│   ├── _CodeSignature (codesign information generated by Apple)
│   ├── Frameworks
│   ├── PlugIns
│   ├── SharedSupport
```

Подробнее см. [официальную документацию](https://developer.apple.com/library/archive/documentation/CoreFoundation/Conceptual/CFBundles/BundleTypes/BundleTypes.html).

## Нативная конфигурация

Бандл приложения настраивается файлом `Info.plist`, который содержит пары «ключ—значение» с идентификацией приложения и значениями конфигурации, считываемыми macOS.

Tauri автоматически настраивает наиболее важные свойства, такие как имя бинарного файла приложения, версия, идентификатор бандла, минимальная версия системы и другое.

Чтобы расширить файл конфигурации, создайте файл `Info.plist` в папке `src-tauri` и включите нужные пары «ключ—значение»:

```xml title="src-tauri/Info.plist"
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
	<key>NSCameraUsageDescription</key>
	<string>Request camera access for WebRTC</string>
	<key>NSMicrophoneUsageDescription</key>
	<string>Request microphone access for WebRTC</string>
</dict>
</plist>
```

Этот файл `Info.plist` объединяется со значениями, генерируемыми CLI Tauri. Будьте осторожны при переопределении значений по умолчанию, таких как версия приложения, поскольку они могут конфликтовать с другими значениями конфигурации и вызывать непредвиденное поведение.

Подробнее см. [официальную документацию Info.plist][official Info.plist documentation].

### Локализация Info.plist

Сам по себе файл `Info.plist` поддерживает только один язык, обычно английский. Если вы хотите поддерживать несколько языков, вы можете создать файлы `InfoPlist.strings` для каждого дополнительного языка. Каждый файл находится в своей собственной языковой директории `lproj` внутри директории `Resources` в бандле приложения.

Чтобы автоматически включать эти файлы в бандл, вы можете использовать функцию [resources] от Tauri. Для этого создайте структуру файлов в проекте по следующему образцу:

```
├── src-tauri
│   ├── tauri.conf.json
│   ├── infoplist
│   │   ├── de.lproj
│   │   │   ├── InfoPlist.strings
│   │   ├── fr.lproj
│   │   │   ├── InfoPlist.strings
```

Хотя имя директории `infoplist` можно выбирать свободно, при условии что вы обновите его в конфигурации ресурсов ниже, директории `lproj` должны следовать соглашению об именовании `<lang-code>.lproj`, а файлы каталога строк должны называться `InfoPlist.strings` (заглавные i и p). В большинстве случаев код языка должен быть двухбуквенным кодом согласно [BCP 47].

Для примера `Info.plist`, показанного выше, файл `de.lproj > InfoPlist.strings` может выглядеть так:

```ini title="de.lproj/InfoPlist.strings"
NSCameraUsageDescription = "Kamera Zugriff wird benötigt für WebRTC Funktionalität";
NSMicrophoneUsageDescription = "Mikrofon Zugriff wird benötigt für WebRTC Funktionalität";
```

Наконец, заставьте Tauri подхватить эти файлы с помощью упомянутой выше функции ресурсов:

```json title="src-tauri/tauri.conf.json"
{
  "bundle": {
    "resources": {
      "infoplist/**": "./"
    }
  }
}
```

## Полномочия

Полномочие (entitlement) — это специальная пара «ключ—значение» конфигурации Apple, которая действует как право или привилегия, предоставляющие вашему приложению определённые возможности, например выступать в роли почтового клиента по умолчанию или использовать функцию App Sandbox.

Полномочия применяются при подписи вашего приложения. Подробнее см. [документацию по подписи кода][code signing documentation].

Чтобы определить полномочия, требуемые вашим приложением, вы должны создать файл полномочий и настроить Tauri на его использование.

1. Создайте файл `Entitlements.plist` в папке `src-tauri` и настройте пары «ключ—значение», требуемые вашему приложению:

```xml title="src-tauri/Entitlements.plist"
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>com.apple.security.app-sandbox</key>
    <true/>
</dict>
</plist>
```

2. Настройте Tauri на использование файла Entitlements.plist:

```json title="tauri.conf.json" ins={4}
{
  "bundle": {
    "macOS": {
      "entitlements": "./Entitlements.plist"
    }
  }
}
```

Подробнее см. [официальную документацию](https://developer.apple.com/documentation/bundleresources/entitlements).

## Минимальная версия системы

По умолчанию ваше приложение Tauri поддерживает macOS 10.13 и выше. Если вы используете API, требующий более новой системы macOS, и хотите закрепить это требование в бандле приложения, вы можете настроить значение [`tauri.conf.json > bundle > macOS > minimumSystemVersion`]:

```json title="tauri.conf.json" ins={4}
{
  "bundle": {
    "macOS": {
      "minimumSystemVersion": "12.0"
    }
  }
}
```

## Включение фреймворков macOS

Если вашему приложению требуются дополнительные фреймворки macOS для работы, вы можете перечислить их в конфигурации [`tauri.conf.json > bundle > macOS > frameworks`]. Список фреймворков может включать системные или собственные фреймворки и файлы dylib.

```json title="tauri.conf.json" ins={4-8}
{
  "bundle": {
    "macOS": {
      "frameworks": [
        "CoreAudio",
        "./libs/libmsodbcsql.18.dylib",
        "./frameworks/MyApp.framework"
      ]
    }
  }
}
```

:::note

- Чтобы сослаться на системный фреймворк, вы можете просто использовать его имя (без расширения .framework) вместо абсолютного пути
- Системные фреймворки должны находиться либо в `$HOME/Library/Frameworks`, `/Library/Frameworks/`, либо в `/Network/Library/Frameworks/`
- Чтобы сослаться на локальные фреймворки и файлы dylib, вы должны использовать полный путь к фреймворку относительно директории `src-tauri`

:::

## Добавление собственных файлов

Вы можете использовать конфигурацию [`tauri.conf.json > bundle > macOS > files`], чтобы добавить собственные файлы в бандл приложения; она сопоставляет путь назначения с его источником относительно файла `tauri.conf.json`. Файлы добавляются в папку `<product-name>.app/Contents`.

```json title="tauri.conf.json" ins={4-7}
{
  "bundle": {
    "macOS": {
      "files": {
        "embedded.provisionprofile": "./profile-name.provisionprofile",
        "SharedSupport/docs.md": "./docs/index.md"
      }
    }
  }
}
```

В приведённом выше примере файл `profile-name.provisionprofile` копируется в `<product-name>.app/Contents/embedded.provisionprofile`, а файл `docs/index.md` копируется в `<product-name>.app/Contents/SharedSupport/docs.md`.
