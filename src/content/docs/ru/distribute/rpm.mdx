## Ограничения

Ключевые библиотеки, такие как glibc, часто нарушают совместимость со старыми системами. Поэтому вы должны собирать своё приложение Tauri, используя самую старую базовую систему, которую планируете поддерживать и которая также предоставляет требуемые WebKitGTK 4.1 пакеты Tauri v2. Ubuntu 22.04 и Debian 12 являются подходящими примерами базовых систем, поскольку они предоставляют `libwebkit2gtk-4.1-dev` из своих стандартных репозиториев пакетов. Сборка на более новой базовой системе может повысить минимальную требуемую версию glibc, поэтому при запуске на более старой системе вы можете столкнуться с ошибкой времени выполнения, например `/usr/lib/libc.so.6: version 'GLIBC_2.33' not found`. Мы рекомендуем использовать контейнер Docker или GitHub Actions для сборки приложения Tauri для Linux.

Подробнее см. проблемы [tauri-apps/tauri#1355](https://github.com/tauri-apps/tauri/issues/1355) и [rust-lang/rust#57497](https://github.com/rust-lang/rust/issues/57497), а также [руководство по AppImage](https://docs.appimage.org/reference/best-practices.html#binaries-compiled-on-old-enough-base-system).

## Настройка пакета RPM

Tauri позволяет настроить пакет RPM, добавляя скрипты, задавая зависимости, добавляя лицензию, включая собственные файлы и многое другое. Подробную информацию о настраиваемых параметрах см. в разделе: [RpmConfig](/reference/config/#rpmconfig).

### Добавление скриптов post, pre-install/remove в пакет

Менеджер пакетов RPM позволяет запускать скрипты до или после установки или удаления пакета. Например, вы можете использовать эти скрипты для запуска службы после установки пакета.

Вот пример того, как добавить эти скрипты:

1. Создайте папку с именем `scripts` в директории `src-tauri` вашего проекта.

```bash
mkdir src-tauri/scripts
```

2. Создайте файлы скриптов в этой папке.

```bash
touch src-tauri/scripts/postinstall.sh \
touch src-tauri/scripts/preinstall.sh \
touch src-tauri/scripts/preremove.sh \
touch src-tauri/scripts/postremove.sh
```

Теперь, если мы заглянем внутрь `/src-tauri/scripts`, мы увидим:

```bash
ls src-tauri/scripts/
postinstall.sh  postremove.sh  preinstall.sh  preremove.sh
```

3. Добавьте некоторое содержимое в скрипты

```bash title="preinstall.sh"
echo "-------------"
echo "This is pre"
echo "Install Value: $1"
echo "Upgrade Value: $1"
echo "Uninstall Value: $1"
echo "-------------"
```

```bash title="postinstall.sh"
echo "-------------"
echo "This is post"
echo "Install Value: $1"
echo "Upgrade Value: $1"
echo "Uninstall Value: $1"
echo "-------------"
```

```bash title="preremove.sh"
echo "-------------"
echo "This is preun"
echo "Install Value: $1"
echo "Upgrade Value: $1"
echo "Uninstall Value: $1"
echo "-------------"
```

```bash title="postremove.sh"
echo "-------------"
echo "This is postun"
echo "Install Value: $1"
echo "Upgrade Value: $1"
echo "Uninstall Value: $1"
echo "-------------"
```

4. Добавьте скрипты в файл `tauri.conf.json`

```json title="tauri.conf.json"
{
  "bundle": {
    "linux": {
      "rpm": {
        "epoch": 0,
        "files": {},
        "release": "1",
        // add the script here
        "preInstallScript": "/path/to/your/project/src-tauri/scripts/prescript.sh",
        "postInstallScript": "/path/to/your/project/src-tauri/scripts/postscript.sh",
        "preRemoveScript": "/path/to/your/project/src-tauri/scripts/prescript.sh",
        "postRemoveScript": "/path/to/your/project/src-tauri/scripts/postscript.sh"
      }
    }
  }
}
```

### Настройка Conflict, Provides, Depends, Files, Obsoletes, DesktopTemplate и Epoch

- **conflict**: предотвращает установку пакета, если он конфликтует с другим пакетом. Например, если вы обновляете пакет RPM, от которого зависит ваше приложение, а новая версия несовместима с вашим приложением.

- **provides**: перечисляет зависимости RPM, которые предоставляет ваше приложение.

- **depends**: перечисляет зависимости RPM, необходимые вашему приложению для работы.

- **files**: указывает, какие файлы включить в пакет.

- **obsoletes**: перечисляет зависимости RPM, которые ваше приложение делает устаревшими.

:::note
Если этот пакет установлен, пакеты, указанные как «obsoletes», будут автоматически удалены, если они присутствуют.
:::

- **desktopTemplate**: добавляет собственный файл desktop в пакет.

- **epoch**: определяет взвешенные зависимости на основе номеров версий.

:::caution
Не рекомендуется использовать epoch без необходимости, так как это изменяет способ сравнения версий пакетов менеджером пакетов. Дополнительную информацию об epoch см.: [RPM Packaging Guide](https://rpm-packaging-guide.github.io/#epoch-scriptlets-and-triggers).
:::

Чтобы использовать эти параметры, добавьте следующее в ваш `tauri.conf.json` :

```json title="tauri.conf.json"
{
  "bundle": {
    "linux": {
      "rpm": {
        "postRemoveScript": "/path/to/your/project/src-tauri/scripts/postscript.sh",
        "conflicts": ["oldLib.rpm"],
        "depends": ["newLib.rpm"],
        "obsoletes": ["veryoldLib.rpm"],
        "provides": ["coolLib.rpm"],
        "desktopTemplate": "/path/to/your/project/src-tauri/desktop-template.desktop"
      }
    }
  }
}
```

### Добавление лицензии в пакет

Чтобы добавить лицензию в пакет, добавьте следующее в файл `src-tauri/cargo.toml` или `src-tauri/tauri.conf.json`:

```toml title="src-tauri/cargo.toml"
[package]
name = "tauri-app"
version = "0.0.0"
description = "A Tauri App"
authors = ["you"]
edition = "2021"
license = "MIT" # add the license here
# ...  rest of the file
```

И для `src-tauri/tauri.conf.json`

```json title="src-tauri/tauri.conf.json"
{
  "bundle": {
    "licenseFile": "../LICENSE", // put the path to the license file here
    "license": "MIT" // add the license here
  }
}
```

## Сборка пакета RPM

Чтобы собрать пакет RPM, вы можете использовать следующую команду:

<CommandTabs
  npm="npm run tauri build"
  yarn="yarn tauri build"
  pnpm="pnpm tauri build"
  deno="deno task tauri build"
  bun="bun tauri build"
  cargo="cargo tauri build"
/>

Эта команда соберёт пакет RPM в директории `src-tauri/target/release/bundle/rpm`.

## Подпись пакета RPM

Tauri позволяет подписать пакет ключом, который есть в вашей системе, во время процесса сборки. Для этого вам потребуется сгенерировать ключ GPG.

#### Генерация ключа GPG

Чтобы сгенерировать ключ GPG, вы можете использовать следующую команду:

```bash
gpg --gen-key
```

Следуйте инструкциям для генерации ключа.

После генерации ключа вам нужно будет добавить его в переменную окружения. Вы можете сделать это, добавив следующее в файл .bashrc или .zshrc или просто экспортировать его в терминале:

```bash
export TAURI_SIGNING_RPM_KEY=$(cat /home/johndoe/my_super_private.key)
```

Если у вас есть парольная фраза для ключа, вы можете добавить её в переменную окружения:

```bash
export TAURI_SIGNING_RPM_KEY_PASSPHRASE=password
```

Теперь вы можете собрать пакет следующей командой:

<CommandTabs
  npm="npm run tauri build"
  yarn="yarn tauri build"
  pnpm="pnpm tauri build"
  deno="deno task tauri build"
  bun="bun tauri build"
  cargo="cargo tauri build"
/>

### Проверка подписи

:::note
Это следует делать только для локального тестирования подписи.
:::

Перед проверкой подписи вам нужно будет создать и импортировать открытый ключ в базу данных RPM:

```bash
gpg --export -a 'Tauri-App' > RPM-GPG-KEY-Tauri-App
```

```bash
sudo rpm --import RPM-GPG-KEY-Tauri-App
```

Теперь, когда ключ импортирован, нам нужно отредактировать файл `~/.rpmmacros`, чтобы использовать ключ.

```bash title="~/.rpmmacros"
%_signature gpg
%_gpg_path /home/johndoe/.gnupg
%_gpg_name Tauri-App
%_gpgbin /usr/bin/gpg2
%__gpg_sign_cmd %{__gpg} \
    gpg --force-v3-sigs --digest-algo=sha1 --batch --no-verbose --no-armor \
    --passphrase-fd 3 --no-secmem-warning -u "%{_gpg_name}" \
    -sbo %{__signature_filename} %{__plaintext_filename}
```

Наконец, вы можете проверить пакет с помощью следующей команды:

```bash
rpm  -v --checksig tauri-app-0.0.0-1.x86_64.rpm
```

## Отладка пакета RPM

В этом разделе мы рассмотрим, как отлаживать пакет RPM, проверяя содержимое пакета и получая информацию о пакете.

### Получение информации о пакете

Чтобы получить информацию о вашем пакете, такую как версия, выпуск и архитектура, используйте следующую команду:

```bash
rpm -qip package_name.rpm
```

### Запрос конкретной информации о пакете

Например, если вы хотите получить имя, версию, выпуск, архитектуру и размер пакета, используйте следующую команду:

```bash
rpm  -qp --queryformat '[%{NAME} %{VERSION} %{RELEASE} %{ARCH} %{SIZE}\n]' package_name.rpm
```

:::note
_`--queryformat`_ — это строка формата, которую можно использовать для получения конкретной информации о пакете. Информация, которую можно получить, берётся из команды rpm -qip.
:::

### Проверка содержимого пакета

Чтобы проверить содержимое пакета, используйте следующую команду:

```bash
rpm -qlp package_name.rpm
```

Эта команда выведет список всех файлов, включённых в пакет.

### Отладка скриптов

Чтобы отладить скрипты post/pre-install/remove, используйте следующую команду:

```bash
rpm -qp --scripts package_name.rpm
```

Эта команда выведет содержимое скриптов.

### Проверка зависимостей

Чтобы проверить зависимости пакета, используйте следующую команду:

```bash
rpm -qp --requires package_name.rpm
```

### Вывод списка пакетов, зависимых от конкретного пакета

Чтобы вывести список пакетов, зависимых от конкретного пакета, используйте следующую команду:

```bash
rpm -q --whatrequires package_name.rpm
```

### Отладка проблем установки

Если вы столкнулись с проблемами во время установки пакета RPM, вы можете использовать параметр `-vv` (очень подробный), чтобы получить детальный вывод:

```bash
rpm -ivvh package_name.rpm
```

Или для уже установленного пакета:

```bash
rpm -Uvvh package_name.rpm
```

## Кросс-компиляция для устройств на базе ARM

В этом руководстве рассматривается ручная компиляция. Ознакомьтесь с нашим [руководством по GitHub Action](/ru/distribute/pipelines/github/#компиляция-на-arm-раннере), где приведён пример рабочего процесса, использующего QEMU для сборки приложения. Это будет гораздо медленнее, но также позволит собирать AppImages.

Ручная компиляция подходит, когда вам не нужно часто компилировать приложение и вы предпочитаете однократную настройку. Следующие шаги предполагают использование дистрибутива Linux на основе Debian/Ubuntu.

<Steps>

1. #### Установите целевые компоненты Rust для нужной архитектуры
   - Для ARMv7 (32-бит): `rustup target add armv7-unknown-linux-gnueabihf`
   - Для ARMv8 (ARM64, 64-бит): `rustup target add aarch64-unknown-linux-gnu`

2. #### Установите соответствующий линковщик для выбранной архитектуры
   - Для ARMv7: `sudo apt install gcc-arm-linux-gnueabihf`
   - Для ARMv8 (ARM64): `sudo apt install gcc-aarch64-linux-gnu`

3. #### Откройте или создайте файл `<project-root>/.cargo/config.toml` и добавьте следующие конфигурации соответственно

   ```toml
   [target.armv7-unknown-linux-gnueabihf]
   linker = "arm-linux-gnueabihf-gcc"

   [target.aarch64-unknown-linux-gnu]
   linker = "aarch64-linux-gnu-gcc"
   ```

4. #### Включите соответствующую архитектуру в менеджере пакетов
   - Для ARMv7: `sudo dpkg --add-architecture armhf`
   - Для ARMv8 (ARM64): `sudo dpkg --add-architecture arm64`

5. #### Настройка источников пакетов

   В Debian этот шаг обычно не нужен, но в других дистрибутивах вам может потребоваться отредактировать /etc/apt/sources.list, чтобы добавить вариант архитектуры ARM. Например, в Ubuntu 22.04 добавьте эти строки в конец файла (не забудьте заменить jammy на кодовое имя вашей версии Ubuntu):

   ```
   deb [arch=armhf,arm64] http://ports.ubuntu.com/ubuntu-ports jammy main restricted
   deb [arch=armhf,arm64] http://ports.ubuntu.com/ubuntu-ports jammy-updates main restricted
   deb [arch=armhf,arm64] http://ports.ubuntu.com/ubuntu-ports jammy universe
   deb [arch=armhf,arm64] http://ports.ubuntu.com/ubuntu-ports jammy-updates universe
   deb [arch=armhf,arm64] http://ports.ubuntu.com/ubuntu-ports jammy multiverse
   deb [arch=armhf,arm64] http://ports.ubuntu.com/ubuntu-ports jammy-updates multiverse
   deb [arch=armhf,arm64] http://ports.ubuntu.com/ubuntu-ports jammy-backports main restricted universe multiverse
   deb [arch=armhf,arm64] http://ports.ubuntu.com/ubuntu-ports jammy-security main restricted
   deb [arch=armhf,arm64] http://ports.ubuntu.com/ubuntu-ports jammy-security universe
   deb [arch=armhf,arm64] http://ports.ubuntu.com/ubuntu-ports jammy-security multiverse
   ```

   Затем, чтобы избежать проблем с основными пакетами, вы должны добавить правильную основную архитектуру во все остальные строки, которые файл содержал ранее. Для стандартных 64-битных систем вам нужно добавить [arch=amd64]; полный файл в Ubuntu 22.04 тогда будет выглядеть примерно так:

6. #### Обновите информацию о пакетах: `sudo apt-get update && sudo apt-get upgrade -y`

7. #### Установите требуемую библиотеку webkitgtk для выбранной архитектуры
   - Для ARMv7: `sudo apt install libwebkit2gtk-4.1-dev:armhf`
   - Для ARMv8 (ARM64): `sudo apt install libwebkit2gtk-4.1-dev:arm64`

8. #### Установите OpenSSL или используйте версию vendor

   Это не всегда требуется, поэтому вы можете сначала продолжить и проверить, не появляются ли ошибки вида `Failed to find OpenSSL development headers`.
   - Либо установите заголовочные файлы разработчика в масштабе системы:
     - Для ARMv7: `sudo apt install libssl-dev:armhf`
     - Для ARMv8 (ARM64): `sudo apt install libssl-dev:arm64`
   - Либо включите функцию vendor для крейта OpenSSL Rust, которая повлияет на все остальные зависимости Rust, использующие ту же минорную версию. Для этого добавьте следующее в раздел зависимостей в вашем файле `Cargo.toml`:

   ```toml
   openssl-sys = {version = "0.9", features = ["vendored"]}
   ```

9. #### Задайте `PKG_CONFIG_SYSROOT_DIR` в соответствующую директорию в зависимости от выбранной архитектуры
   - Для ARMv7: `export PKG_CONFIG_SYSROOT_DIR=/usr/arm-linux-gnueabihf/`
   - Для ARMv8 (ARM64): `export PKG_CONFIG_SYSROOT_DIR=/usr/aarch64-linux-gnu/`

10. #### Соберите приложение для нужной версии ARM
    - Для ARMv7: cargo tauri build --target armv7-unknown-linux-gnueabihf
    - Для ARMv8 (ARM64): cargo tauri build --target aarch64-unknown-linux-gnu

    Выберите соответствующий набор инструкций в зависимости от того, хотите ли вы кросс-компилировать ваше приложение Tauri для ARMv7 или ARMv8 (ARM64). Обратите внимание, что конкретные шаги могут отличаться в зависимости от вашего дистрибутива Linux и настройки.

</Steps>
