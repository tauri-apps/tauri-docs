Это руководство проведёт вас через процесс обновления вашего приложения Tauri 1.0 до Tauri 2.0.

## Подготовка к мобильной разработке

Мобильный интерфейс Tauri требует, чтобы ваш проект создавал общую библиотеку. Если вы ориентируете своё существующее приложение на мобильные устройства, вы должны изменить свой крейт, чтобы он создавал такой артефакт наряду с исполняемым файлом для настольной версии.

1. Измените манифест Cargo, чтобы он создавал библиотеку. Добавьте следующий блок:

```toml
// src-tauri/Cargo.toml
[lib]
name = "app_lib"
crate-type = ["staticlib", "cdylib", "rlib"]
```

2. Переименуйте `src-tauri/src/main.rs` в `src-tauri/src/lib.rs`. Этот файл будет использоваться совместно для настольных и мобильных целевых платформ.

3. Переименуйте заголовок функции `main` в `lib.rs` следующим образом:

```rust
// src-tauri/src/lib.rs
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    // your code here
}
```

Макрос `tauri::mobile_entry_point` подготавливает вашу функцию к выполнению на мобильных устройствах.

4. Заново создайте файл `main.rs`, вызывающий общую функцию run:

```rust
// src-tauri/src/main.rs
#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]

fn main() {
  app_lib::run();
}
```

## Автоматическая миграция

:::danger

Эта команда не заменяет данное руководство! Пожалуйста, прочитайте страницу _целиком_, независимо от того, решили ли вы использовать команду.

:::

CLI Tauri v2 включает команду `migrate`, которая автоматизирует большую часть процесса и помогает завершить миграцию:

<CommandTabs
  npm="npm install @tauri-apps/cli@latest
    npm run tauri migrate"
  yarn="yarn upgrade @tauri-apps/cli@latest
    yarn tauri migrate"
  pnpm="pnpm update @tauri-apps/cli@latest
    pnpm tauri migrate"
  cargo='cargo install tauri-cli --version "^2.0.0" --locked
    cargo tauri migrate'
/>

Узнайте больше о команде `migrate` в [справочнике интерфейса командной строки](/reference/cli/#migrate).

## Сводка изменений

Ниже представлена сводка изменений от Tauri 1.0 к Tauri 2.0:

### Конфигурация Tauri

- `package > productName` и `package > version` перемещены в объект верхнего уровня.
- имя бинарного файла больше не переименовывается автоматически в соответствии с `productName`, поэтому необходимо добавить строку `mainBinaryName` в объект верхнего уровня, соответствующую `productName`.
- `package` удалён.
- ключ `tauri` переименован в `app`.
- `tauri > allowlist` удалён. См. [Миграция разрешений](#миграция-разрешений).
- `tauri > allowlist > protocol > assetScope` перемещён в `app > security > assetProtocol > scope`. См. [Область действия протокола ресурсов](/ru/security/asset-protocol/) для параметров `enable`, glob-шаблонов, `requireLiteralLeadingDot` и динамических путей.
- `tauri > cli` перемещён в `plugins > cli`.
- `tauri > windows > fileDropEnabled` переименован в `app > windows > dragDropEnabled`.
- `tauri > updater > active` удалён.
- `tauri > updater > dialog` удалён.
- `tauri > updater` перемещён в `plugins > updater`.
- `bundle > createUpdaterArtifacts` добавлен; его необходимо задать при использовании обновлятеля приложения.
  - установите значение `v1Compatible` при обновлении со v1-приложений, которые уже были распространены. См. [руководство по обновлятелю](/ru/plugin/updater/) для получения дополнительной информации.
- `tauri > systemTray` переименован в `app > trayIcon`.
- `tauri > pattern` перемещён в `app > security > pattern`.
- `tauri > bundle` перемещён на верхний уровень.
- `tauri > bundle > identifier` перемещён в объект верхнего уровня.
- `tauri > bundle > dmg` перемещён в `bundle > macOS > dmg`
- `tauri > bundle > deb` перемещён в `bundle > linux > deb`
- `tauri > bundle > appimage` перемещён в `bundle > linux > appimage`
- `tauri > bundle > macOS > license` удалён; вместо него используйте `bundle > licenseFile`.
- `tauri > bundle > windows > wix > license` удалён; вместо него используйте `bundle > licenseFile`.
- `tauri > bundle > windows > nsis > license` удалён; вместо него используйте `bundle > licenseFile`.
- `tauri > bundle > windows > webviewFixedRuntimePath` удалён; вместо него используйте `bundle > windows > webviewInstallMode`.
- `build > withGlobalTauri` перемещён в `app > withGlobalTauri`.
- `build > distDir` переименован в `frontendDist`.
- `build > devPath` переименован в `devUrl`.

[Справочник API конфигурации Tauri 2.0](/reference/config/)

### Новые возможности Cargo

- linux-protocol-body: включает разбор тела запроса пользовательского протокола, позволяя IPC использовать его. Требуется webkit2gtk 2.40.

### Удалённые возможности Cargo

- reqwest-client: reqwest теперь единственный поддерживаемый клиент.
- reqwest-native-tls-vendored: вместо него используйте `native-tls-vendored`.
- process-command-api: вместо него используйте плагин `shell` (см. инструкции в следующем разделе).
- shell-open-api: вместо него используйте плагин `shell` (см. инструкции в следующем разделе).
- windows7-compat: перемещён в плагин `notification`.
- updater: теперь модуль обновления является плагином.
- linux-protocol-headers: теперь включён по умолчанию, поскольку мы повысили минимальную версию webkit2gtk.
- system-tray: переименован в `tray-icon`.

### Изменения крейтов Rust

- модуль `api` удалён. Каждый модуль API можно найти в плагине Tauri.
- модуль `api::dialog` удалён. Вместо него используйте `tauri-plugin-dialog`. [Миграция](#миграция-на-плагин-диалоговых-окон)
- модуль `api::file` удалён. Вместо него используйте [`std::fs`](https://doc.rust-lang.org/std/fs/) из Rust.
- модуль `api::http` удалён. Вместо него используйте `tauri-plugin-http`. [Миграция](#миграция-на-плагин-http)
- модуль `api::ip` переписан и перемещён в `tauri::ipc`. Ознакомьтесь с новыми API, особенно с `tauri::ipc::Channel`.
- функции модуля `api::path` и `tauri::PathResolved` перемещены в `tauri::Manager::path`. [Миграция](#миграция-путей-на-менеджер-tauri)
- API `api::process::Command`, `tauri::api::shell` и `tauri::Manager::shell_scope` удалены. Вместо них используйте `tauri-plugin-shell`. [Миграция](#миграция-на-плагин-shell)
- `api::process::current_binary` и `tauri::api::process::restart` перемещены в `tauri::process`.
- модуль `api::version` удалён. Вместо него используйте [крейт semver](https://docs.rs/semver/latest/semver/).
- `App::clipboard_manager` и `AppHandle::clipboard_manager` удалены. Вместо них используйте `tauri-plugin-clipboard`. [Миграция](#миграция-на-плагин-буфера-обмена)
- `App::get_cli_matches` удалён. Вместо него используйте `tauri-plugin-cli`. [Миграция](#миграция-на-плагин-cli)
- `App::global_shortcut_manager` и `AppHandle::global_shortcut_manager` удалены. Вместо них используйте `tauri-plugin-global-shortcut`. [Миграция](#миграция-на-плагин-глобальных-горячих-клавиш)
- `Manager::fs_scope` удалён. К области действия файловой системы можно получить доступ через `tauri_plugin_fs::FsExt`.
- `Plugin::PluginApi` теперь принимает конфигурацию плагина вторым аргументом.
- `Plugin::setup_with_config` удалён. Вместо него используйте обновлённый `tauri::Plugin::PluginApi`.
- `scope::ipc::RemoteDomainAccessScope::enable_tauri_api` и `scope::ipc::RemoteDomainAccessScope::enables_tauri_api` удалены. Включайте каждый базовый плагин по отдельности через `scope::ipc::RemoteDomainAccessScope::add_plugin`.
- `scope::IpcScope` удалён; вместо него используйте `scope::ipc::Scope`.
- `scope::FsScope`, `scope::GlobPattern` и `scope::FsScopeEvent` удалены; вместо них используйте соответственно `scope::fs::Scope`, `scope::fs::Pattern` и `scope::fs::Event`.
- модуль `updater` удалён. Вместо него используйте `tauri-plugin-updater`. [Миграция](#миграция-на-плагин-обновления)
- поле `Env.args` удалено; вместо него используйте поле `Env.args_os`.
- API `Menu`, `MenuEvent`, `CustomMenuItem`, `Submenu`, `WindowMenuEvent`, `MenuItem` и `Builder::on_menu_event` удалены. [Миграция](#миграция-на-меню)
- API `SystemTray`, `SystemTrayHandle`, `SystemTrayMenu`, `SystemTrayMenuItemHandle`, `SystemTraySubmenu`, `MenuEntry` и `SystemTrayMenuItem` удалены. [Миграция](#миграция-на-модуль-значка-трея)

### Система событий

Система событий была переработана, чтобы ею было проще пользоваться. Вместо использования источника события теперь применяется более простая реализация, основанная на целевых объектах событий.

- Функция `emit` теперь отправляет событие всем слушателям событий.
- Добавлена новая функция `emit_to`/`emitTo` для запуска события для конкретного целевого объекта.
- `emit_filter` теперь фильтрует на основе [`EventTarget`](https://docs.rs/tauri/2.0.0/tauri/event/enum.EventTarget.html) вместо окна.
- `listen_global` переименован в `listen_any`. Теперь он прослушивает все события независимо от их фильтров и целевых объектов.
- JavaScript: `event.listen()` ведёт себя аналогично `listen_any`. Теперь он прослушивает все события независимо от их фильтров и целевых объектов, если только целевой объект не задан в `Options`.
- JavaScript: `WebviewWindow.listen` и др. прослушивают только события, отправляемые соответствующему `EventTarget`.

### Поддержка нескольких WebView

Tauri v2 вводит поддержку нескольких WebView, которая в настоящее время находится за флагом функции `unstable`. Для её поддержки мы переименовали тип Rust `Window` в `WebviewWindow`, а функцию Manager `get_window` — в `get_webview_window`.

Тип JS API `WebviewWindow` теперь повторно экспортируется из `@tauri-apps/api/webviewWindow` вместо `@tauri-apps/api/window`.

### Новый URL источника в Windows

В Windows файлы фронтенда в производственных приложениях теперь размещаются на `http://tauri.localhost` вместо `https://tauri.localhost`. Из-за этого IndexedDB, LocalStorage и Cookies будут сброшены, если в v1 не использовался `dangerousUseHttpScheme`. Чтобы предотвратить это, вы можете установить `app > windows > useHttpsScheme` в `true` или использовать `WebviewWindowBuilder::use_https_scheme`, чтобы продолжать использовать схему `https`.

## Подробные шаги миграции

Типовые сценарии, с которыми вы можете столкнуться при миграции вашего приложения Tauri 1.0 на Tauri 2.0.

### Миграция на базовый модуль

Модуль `@tauri-apps/api/tauri` был переименован в `@tauri-apps/api/core`. Просто переименуйте импорт модуля:

```diff
- import { invoke } from "@tauri-apps/api/tauri"
+ import { invoke } from "@tauri-apps/api/core"
```

### Миграция на плагин CLI

API Rust `App::get_cli_matches` и JavaScript `@tauri-apps/api/cli` удалены. Вместо них используйте плагин `@tauri-apps/plugin-cli`:

1. Добавьте в зависимости cargo:

```toml
# Cargo.toml
[dependencies]
tauri-plugin-cli = "2"
```

2. Используйте в проекте на JavaScript или Rust:

<TabItem label="JavaScript">

```rust
fn main() {
    tauri::Builder::default()
        .plugin(tauri_plugin_cli::init())
}
```

```json
// package.json
{
  "dependencies": {
    "@tauri-apps/plugin-cli": "^2.0.0"
  }
}
```

```javascript
import { getMatches } from '@tauri-apps/plugin-cli';
const matches = await getMatches();
```

</TabItem>

```rust
fn main() {
    use tauri_plugin_cli::CliExt;
    tauri::Builder::default()
```

### Миграция на плагин файловой системы

API Rust `tauri::api::file` и JavaScript `@tauri-apps/api/fs` удалены. Вместо них используйте [`std::fs`](https://doc.rust-lang.org/std/fs/) для Rust и плагин `@tauri-apps/plugin-fs` для JavaScript:

1. Добавьте в зависимости cargo:

```toml
# Cargo.toml
[dependencies]
tauri-plugin-fs = "2"
```

2. Используйте в проекте на JavaScript или Rust:

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```rust
fn main() {
    tauri::Builder::default()
        .plugin(tauri_plugin_fs::init())
}
```

```json
// package.json
{
  "dependencies": {
    "@tauri-apps/plugin-fs": "^2.0.0"
  }
}
```

```javascript
import { mkdir, BaseDirectory } from '@tauri-apps/plugin-fs';
await mkdir('db', { baseDir: BaseDirectory.AppLocalData });
```

Некоторые функции и типы были переименованы или удалены:

- `Dir` alias enum удалён; используйте `BaseDirectory`.
- Интерфейсы и псевдонимы типов `FileEntry`, `FsBinaryFileOption`, `FsDirOptions`, `FsOptions`, `FsTextFileOption` и `BinaryFileContents` удалены и заменены новыми интерфейсами, подходящими для каждой функции.
- `createDir` переименован в `mkdir`.

#### События меню

API Rust `tauri::Builder::on_menu_event` удалён. Вместо него используйте `tauri::App::on_menu_event` или `tauri::AppHandle::on_menu_event`:

```rust
use tauri::menu::{CheckMenuItemBuilder, MenuBuilder, MenuItemBuilder};

tauri::Builder::default()
    .setup(|app| {
        let toggle = MenuItemBuilder::with_id("toggle", "Toggle").build(app)?;
        let check = CheckMenuItemBuilder::new("Mark").build(app)?;
        let menu = MenuBuilder::new(app).items(&[&toggle, &check]).build()?;

        app.set_menu(menu)?;

        app.on_menu_event(move |app, event| {
            if event.id() == check.id() {
                println!("`check` triggered, do something! is checked? {}", check.is_checked().unwrap());
            } else if event.id() == "toggle" {
                println!("toggle triggered!");
            }
        });
        Ok(())
    })
```

Обратите внимание, что есть два способа проверить, какой пункт меню был выбран: переместить пункт в замыкание обработчика событий и сравнить идентификаторы либо определить пользовательский идентификатор для пункта через конструктор `with_id` и использовать эту строку идентификатора для сравнения.

:::tip
Пункты меню можно использовать совместно в разных меню, и событие меню привязано к пункту меню, а не к меню или окну. Если вы не хотите, чтобы при выборе пункта меню срабатывали все слушатели, не используйте общие пункты меню, а создавайте отдельные экземпляры, которые можно передать в замыкание `tauri::WebviewWindow/WebviewWindowBuilder::on_menu_event`.
:::

`tauri::SystemTray::on_event` был разделён на `tauri::tray::TrayIconBuilder::on_menu_event` и `tauri::tray::TrayIconBuilder::on_tray_icon_event`:

```rust
use tauri::{
    menu::{MenuBuilder, MenuItemBuilder},
    tray::{MouseButton, MouseButtonState, TrayIconBuilder, TrayIconEvent},
};

tauri::Builder::default()
    .setup(|app| {

        let menu = MenuBuilder::new(app).items(&[&toggle]).build()?;

            .menu(&menu)

                "toggle" => {
                    println!("toggle clicked");
                }
                _ => (),
            })
            .on_tray_icon_event(|tray, event| {
                if let TrayIconEvent::Click {
                        button: MouseButton::Left,
                        button_state: MouseButtonState::Up,
                        ..
                } = event
                {
                    let app = tray.app_handle();
                    if let Some(webview_window) = app.get_webview_window("main") {
                       let _ = webview_window.unminimize();
                       let _ = webview_window.show();
                       let _ = webview_window.set_focus();
                    }
                }
            })
            .build(app)?;

        Ok(())
    })
```

В Tauri v1 внешние бинарные файлы и их аргументы определялись в списке разрешений. В v2 используйте новую систему разрешений. Прочитайте [Миграция разрешений](#миграция-разрешений) для получения дополнительной информации.

На стороне JavaScript убедитесь, что вы выполнили [миграцию на плагин Shell](#миграция-на-плагин-shell).

На стороне Rust API `tauri::api::process` удалено. Вместо него используйте API `tauri_plugin_shell::ShellExt` и `tauri_plugin_shell::process::CommandEvent`. Прочитайте руководство [Встраивание внешних бинарных файлов](/ru/develop/sidecar/#запуск-из-rust), чтобы понять, как это сделать.

Флаг функции «process-command-api» был удалён в v2. Поэтому для запуска внешних бинарных файлов больше не требуется определять эту функцию в конфигурации Tauri.

### Миграция разрешений

Список разрешений v1 был переписан в совершенно новую систему разрешений, которая работает для отдельных плагинов и допускает гораздо более гибкую настройку для поддержки нескольких окон и удалённых URL.

Эта новая система работает как список управления доступом (ACL), где можно разрешать или запрещать команды, назначать разрешения конкретному набору окон и доменов, а также определять области доступа.

Чтобы включить разрешения для своего приложения, необходимо создать файлы возможностей в папке `src-tauri/capabilities`, и Tauri автоматически настроит всё остальное.

Команда CLI `migrate` автоматически анализирует ваш список разрешений v1 и создаёт соответствующий файл возможностей.

Чтобы узнать больше о разрешениях и возможностях, см. [документацию по безопасности](/ru/security/).
